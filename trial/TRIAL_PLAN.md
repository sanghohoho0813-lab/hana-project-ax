# 비교시험 계획서 — 수기 일정확인 vs 연쇄위험 판단 AX 사용

> **진행요원·채점자용 (참가자 비공개)** — 시나리오 유형이 적혀 있으므로 시험이 끝날 때까지 참가자에게 보여주지 않습니다.
> 벤처기업확인 이의신청용 소규모 전후 비교시험. 기존 프로그램 기능·디자인은 바꾸지 않았고, 시험 준비와 검증 자료만 `trial/`에 두었습니다.

## 0. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 비교 | 같은 관리자가 ① 수기 일정확인(종이 일정표 + 계산기)과 ② AX 시스템 사용으로 각각 판단 |
| 참가자 | 하나정보통신 관리자 2~3명 (코드 P1·P2·P3로만 기록) |
| 문제 | 가상 시나리오 10개 = A세트 5 + B세트 5 (구조·난이도 같음), 연습 2개 |
| 측정 | ① 위험 인지시간 ② 정확히 발견한 위험 건수 ③ 후속 현장 영향 파악 ④ 관리자 조치 후 재판단 시간 |
| 1인 소요 | 약 90분 (2회차 + 휴식) |
| 정답표 | 시험 전에 손계산 → 독립 검산(Python)과 실제 AX 엔진으로 대조, 모두 일치. 파일 지문 고정 (11장) |
| 원칙 | 측정하지 않은 소요시간·개선율은 만들지 않음. 빈 칸은 빈 칸으로 둔다 |

## 1. 목적과 범위

- **확인하려는 것**: 관리자가 여러 현장 일정에서 후속 현장 위험을 찾고, 조치 뒤 다시 판단하는 데 걸리는 시간과 정확도가 AX 시스템 사용 여부에 따라 어떻게 다른지 실제로 잰다.
- **기존 자료와의 관계**: 저장소의 정량 비교(`docs/RISK_ENGINE_TEST_REPORT.md` 6·12장)는 프로그램끼리(기존 정적 검사 vs 엔진)의 자동 비교다. 이번 시험은 **사람의 판단**을 잰다. 데이터도 새로 만들어 겹치지 않는다. (08번 보고서 원문은 확인하지 못했다 — 제출본과 대조 필요)
- **주장하지 않는 것**: 실제 현장 운영 효과(업무 누락·사고 감소), 통계적 유의성, 외부 제품 대비 우수성, 측정하지 않은 개선율.

## 2. 시험 대상 — 기존 AX 시스템 (수정하지 않음)

- 판단: `src/lib/risk-engine.ts`(chain-risk/1.1.0) · `src/lib/priority-engine.ts`(response-priority/1.0.0) — 통합일정 화면과 같은 가정(작업시간 유지, `OPS_ASSUMPTIONS`)으로 실행.
- 표시: 연결별 판단 근거 카드 `RiskLinkCard`, 대응 우선순위 목록 `PriorityList` — 통합일정 화면과 같은 부품.
- 시험용 화면 `trial/dist/AX_trial_screen.html`: 위 코드를 **수정 없이** 묶은 파일 하나(서버 불필요). 시험용으로 더한 것은 시나리오 선택·가림막('열기')·시작 조정 입력 틀뿐이다. 정답표는 들어 있지 않다.
  - 기존 프로그램의 통합일정 화면은 데모 데이터가 고정돼 있어 새 시나리오를 넣을 수 없고, 새 화면을 앱에 넣으려면 기존 메뉴·권한 코드를 고쳐야 하므로 앱 밖의 파일로 만들었다.
  - 기준 프로그램 커밋 `4b23dea`(src/ 최종 변경) · 엔진 소스 지문 `8ec46d13d870` (화면 파일 머리말에 기록).

## 3. 설계 — 교차설계 (같은 사람이 두 방식 모두)

| 참가자 | 1회차 | 2회차 |
|---|---|---|
| P1 | 수기 · A세트 | AX · B세트 |
| P2 | AX · A세트 | 수기 · B세트 |
| P3 (있으면) | 수기 · B세트 | AX · A세트 |
| P4 (선택) | AX · B세트 | 수기 · A세트 |

- 방식 순서(수기 먼저/AX 먼저)와 세트(A/B)를 사람마다 바꿔, 두 번째 회차에 익숙해지는 효과와 세트 난이도 차이를 상쇄한다. 2명이면 P1·P2, 3명이면 P1~P3.
- 시나리오는 세트 안에서 1→5 순서로 푼다. 참가자끼리 서로 보거나 듣지 않게 한 사람씩(또는 다른 방에서) 진행한다.

### 세트 동등성 (A와 B는 같은 유형을 지역·시각만 바꿔 만듦)

| 쌍 | 유형 (참가자 비공개) | 조치 전 위험 | 조치 후 |
|---|---|---|---|
| A1·B1 | 현장 예상 종료 보고로 생기는 지연 1건 + 여유 5분 '주의'(위험 아님) | 1 | 해소 → 0 |
| A2·B2 | 작업개시 지연이 두 현장으로 번지는 연쇄 + 예정표만으로 보이는 이동시간 부족 | 3 | 1 해소 · 1 악화 · 1 유지 → 2 |
| A3·B3 | 지연 보고가 있지만 여유로 흡수(위험 아님) + 예정 시간 겹침 | 1 | 완화(남음) → 1 |
| A4·B4 | 보고 없이 예정 종료 지남(기준시각 추정) + 이미 시작한 현장(판단 대상 아님) + 늦은 작업개시 | 2 | 1 해소 · **1 신규** · 1 유지 → 2 |
| A5·B5 | 완료 보고 지연 + 30분 이상 지연과 그 연쇄 + 여유 0분 '주의' | 3 | 1 해소 · 2 유지 → 2 |
| 세트 합계 | 연결 20건 | **10건** (예정표만으로 보이는 2건, 현장 보고를 반영해야 보이는 8건) | **7건** (해소 4 · 신규 1) · 늦어지는 현장 10곳 |

같은 수가 맞는지는 `trial/check/engine-crosscheck.check.ts` 마지막 항목이 확인한다.

## 4. 공정성 장치

1. **같은 정보**: 수기 시험지와 AX 화면에 같은 일정표·같은 현장 보고 문장 (`trial/lib/scenario.ts`의 `reportsOf`와 `make_print.py`가 같은 규칙으로 만든다).
2. **같은 판단 기준표**: 두 방식 모두 시작 전에 같은 기준표를 같은 대본으로 설명한다(7장). 수기 방식은 계산기·연필 사용 가능.
3. **같은 답안지·같은 제한시간**: 1부 10분, 2부 5분. 시간 초과면 그때까지 적은 것으로 채점하고 '시간 초과'로 표시한다.
4. **같은 시간 측정**: 기록자가 두 방식 모두 같은 도구(`trial/dist/observer_timer.html` 또는 같은 스톱워치)로 잰다. AX 화면은 시간을 재지 않는다.
5. **연습**: 회차마다 그 방식으로 연습 1문항(수기 R1, AX R2)을 먼저 풀고 정답을 설명한다. 연습은 채점하지 않는다.
6. **정답 사전 고정**: 정답표는 시험 전에 만들고 지문(sha256)을 기록했다(11장). 채점 프로그램이 시험 뒤 정답이 바뀌었는지 확인한다.
7. **방식을 가린 채점**: 답안 입력표(`answers.csv`)에는 방식 칸이 없다. 채점자는 답안지의 방식 표시를 가리고 입력한다. 방식은 기록지에서 붙인다.
8. **힌트 금지**: 진행요원·기록자는 답을 알려주거나 반응하지 않는다. 질문에는 "판단 기준표대로 하시면 됩니다"라고만 답한다.

## 7. 진행 순서와 대본 (약 90분)

| 시간 | 내용 |
|---|---|
| 0~5분 | 안내·동의, 참가자 정보 작성 |
| 5~12분 | 판단 기준표 설명 (아래 대본 그대로) |
| 12~20분 | 1회차 방식으로 연습 1문항 → 정답 설명 (AX면 화면 사용법 3분 포함) |
| 20~45분 | 1회차 본시험 5문항 |
| 45~55분 | 휴식 |
| 55~63분 | 2회차 방식으로 연습 1문항 → 정답 설명 |
| 63~88분 | 2회차 본시험 5문항 |
| 88~90분 | 시험 후 한마디(선택), 정리 |

**기준표 설명 대본** — "같은 작업자가 앞 현장을 마치고 다음 현장에 예정 시각까지 도착할 수 있는지 봅니다. 앞 현장이 끝나는 시각은 기준표 2번 순서로 정하고, 이동시간을 더해 도착 시각을 구합니다. 도착이 다음 현장 시작보다 늦으면 위험이고, 늦은 만큼이 부족 분입니다. 늦게 도착한 현장은 끝나는 시각도 밀리니 그다음 현장도 확인하세요. 1부에는 위험 연결과 늦어지는 현장을, 2부에는 조치 카드대로 바꾼 뒤의 위험과 없어진 위험을 적습니다. 다 적으면 '1부 끝', '2부 끝'이라고 말해 주세요. 빠르기와 정확도를 함께 봅니다."

**문항 진행** (두 방식 같음)
1. 수기: 시험지를 엎어 둔다 / AX: 해당 시나리오를 골라 가림막 화면에서 멈춘다. 답안지(그 시나리오)를 둔다.
2. "시작하세요" → 참가자가 뒤집거나 '열기'를 누르는 순간 기록자 ①.
3. "1부 끝" → 기록자 ②. 10분이 되면 "시간이 됐습니다, 멈춰 주세요" 후 ②, 특이사항에 '시간 초과'.
4. 조치 카드를 건네는 순간 기록자 ③. (AX: 참가자가 화면의 '일정 시작 조정'에 직접 입력)
5. "2부 끝" → 기록자 ④. 5분이 되면 멈추게 하고 ④, '시간 초과'.
6. 답안지를 걷는다. 다음 문항.

**AX 화면 사용법 (연습 때 3분)** — 우선순위 목록 → 연결별 판단 근거 카드(위험은 펼쳐져 있음, '영향받는 후속 일정' 표시) → '위험 없는 연결 보기' → '일정 시작 조정'에 현장을 고르고 새 시작 시각을 넣은 뒤 '조정하고 다시 판단' → 위쪽 회색 상자에 바뀐 연결이 나온다.

## 8. 기록 · 입력 · 채점

1. 기록자: 측정 도구의 'CSV 저장'으로 회차마다 파일을 받고, `trial/results/timing.csv`에 행을 이어 붙인다(머리글 한 줄만). 도구를 못 쓰면 기록지의 시각을 같은 형식으로 옮긴다.
2. 채점자: 답안지를 `trial/results/answers.csv`로 옮긴다 (형식은 `trial/results/README.md`). **적힌 그대로** 옮긴다 — 틀린 답도 고치지 않는다. 가능하면 두 사람이 따로 입력해 비교한다.
3. 참가자 정보는 `participants.csv`.
4. `python3 trial/tools/score.py` → `results/summary.json`, `results/scored_trials.csv`, `report/additional_verification.md`.
5. 채점 프로그램이 '확인 필요'를 띄우면(없는 현장 이름, 기록지에 없는 답안 등) 원본 답안지를 보고 입력을 고친다. 추정해서 채우지 않는다.

## 9. 결과 보고 원칙

- 측정값만 쓴다. 놓친 측정은 '기록 없음'으로 두고 이유를 적는다.
- 시간은 중앙값과 범위(최소~최대), 측정 건수 n을 함께 쓴다. 참가자별 값도 함께 싣는다.
- 통계적으로 유의하다고 쓰지 않는다 (참가자 2~3명).
- 개선율을 쓰려면 실측 중앙값끼리만 계산하고 "이번 시험(n=…)의 측정값"이라고 밝힌다. 채점 프로그램은 개선율을 계산하지 않는다.
- 위험 판단 점수는 확률이 아니며, 시험 결과로 실제 현장 효과를 주장하지 않는다.

## 10. 한계

- 참가자가 적고 가상 시나리오다. 실제 운영데이터 시험이 아니다.
- 수기 방식에도 판단 기준표를 줬다 — 평소 업무보다 수기에 유리하다.
- AX 시간에 일정·현장 보고 입력 시간은 들어가지 않는다 (현장 앱 입력으로 들어온 정보라고 가정).
- 시험용 화면은 실제 엔진·부품을 쓰지만 화면 틀은 시험용이다.
- 진행요원이 회사 내부 인원이면 기대 효과가 생길 수 있다 — 대본을 그대로 읽고 반응하지 않는 것으로 줄인다.
