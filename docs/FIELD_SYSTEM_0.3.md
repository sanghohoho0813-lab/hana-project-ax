# 현장 실사용 AX 시스템 0.3.0 — 구조 · 핵심 처리 흐름 · 검증 결과

대상 기술: **복수 현장 업무 위험관리 AX 시스템** (명칭 그대로)
엔진: 연쇄위험 `chain-risk/1.1.0` · 상태편차 `state-deviation/1.0.0` · 대응 우선순위 `response-priority/1.0.0` — **코드 변경 없음**
프로그램: `hana-project-ax@0.3.0` (1차 `63a8c54` · 2차 `6e1476e` · 3차 `e7e9f9a` · 인쇄 수정·시험 보강 `6abfa62` · 문서 커밋)
작성: 2026-11-14

> **읽기 전에 — 무엇을 어디까지 확인했는지**
> - 모든 시험은 이 개발 환경의 **로컬 Supabase(도커)** 에서 했다. 관리자 PC · 기사 A 휴대폰 · 기사 B 휴대폰은 **한 컴퓨터 안의 서로 다른 브라우저 세션 3개**다. 각자 따로 로그인했고, 휴대폰 2개는 휴대폰 화면 크기와 터치를 흉내 냈다.
> - **서로 다른 실제 기기 2대 이상 시험, 현장 참여시험, 실제 업무 데이터는 아직 0건이다.** 운영 Supabase·Vercel 설정을 승인받은 뒤 진행한다 (`docs/FIELD_SYSTEM_DEPLOYMENT.md`).
> - 시험 기록은 모두 검증 시나리오(사건번호 `HT-`, 안전점검 `ST-`)이고 로컬 DB에만 있다. 시각과 작업시간은 시험용 가정값이다. 측정값으로 개선율이나 효과를 계산하지 않았다.
> - 기존 브라우저 저장판(0.2.0) 실증자료와 가상 시험 기록, 기존 시험 코드는 지우지 않았다.

## 3. 핵심 처리 흐름 — 현장 문제 → 해결

| # | 단계 | 누가 | 입력 / 계산 | 남는 기록 | 복수 현장 위험 판단에 어떻게 쓰이나 |
|---|---|---|---|---|---|
| 1 | 문제 발견 | 현장기사 | 발견시각: 지금 · 10분 전 · 30분 전 · 1시간 전 · 모름 (+근거) | `field_cases.discovered_at` · 근거 | 발견→보고 지연(측정 1)이 후속 현장 대응 여유를 얼마나 줄였는지 본다 |
| 2 | 문제 보고 · 지원 요청 | 현장기사 | 유형 · 진행상황 · 지원 항목 · 긴급 · 사진. 보고 시각 = 서버 시각 − 휴대폰 전송 지연 | `field_cases` · `case_photos` | 문제 보고만으로는 위험을 판정하지 않는다. 본사가 무엇이 필요한지 바로 안다 |
| 3 | 변경 예상 종료 | 현장기사 | +30분 · +1시간 · +2시간 · 직접 입력 · **모름** | 같은 트랜잭션에서 기존 `work_events` '예상 종료 보고' 1건 | **엔진 입력.** 모르면 입력하지 않는다. 화면에 '예상 종료 미확인 — 엔진 판단에 반영 안 됨'으로 표시 |
| 4 | 후속 도착 계산 | 엔진 | 예상 종료(보고값) + 이동시간(입력값) → 다음 현장 도착(계산값) | `risk_judgments` 판단 전·후 (서명) | 지연이 어느 현장까지 번지는지(범위)와 얼마나 늦는지(분) |
| 5 | 연쇄위험 · 우선순위 | 엔진 + 관리자 화면 | 위험 연결 수 · 최대 부족시간 · 판단 보류 수 → 사건 정렬 | — | 여러 사건 가운데 무엇부터 지원할지 |
| 6 | 관리자 조치 | 관리자 | 접수 · 담당자 배정 · 지원 조치 결정 · 현장 전달 · 일정 조정 | `case_steps`(추가만) · 기존 `schedule_revisions` | 시스템은 조정안을 만들지 않는다. 관리자가 정한 값만 저장한다 |
| 7 | 재판단 | 엔진 | 조정된 일정으로 다시 계산 | `risk_judgments` | 해소 · 유지 · **조치 뒤 새 위험**을 숨기지 않고 보여 준다 |
| 8 | 해결 기록 | 현장기사 → 관리자 | 현장 해결 보고(해결/못 함) → 관리자 해결 확인 / 미해결 유지 | `case_steps` · 사건 상태 | 발생→해결 소요시간(측정 4) |

**사건 상태**: `보고됨` → (접수) `접수됨` → (배정·결정·전달·조정) `조치 중` → (현장 해결 보고) `현장 해결 보고` 또는 `미해결` → (해결 확인) `해결`. 무효 처리하면 `무효`가 되고, 연결된 예상 종료 기록도 무효가 된다. 접수 전에는 지원 결정을 할 수 없다.

**관리자 우선순위** (`rankCases`, 계산 근거를 이유 문장으로 함께 표시): ① 안전 위험 보고 → ② 긴급 → ③ 엔진이 계산한 후속 현장 위험 수 → ④ 최대 부족시간 → ⑤ 미접수 → ⑥ 기다린 시간.
미처리 사건(보고됨 · 접수됨 · 조치 중 · 현장 해결 보고 · 미해결)은 해결되거나 무효가 될 때까지 목록에 남는다.

**시각 4종을 따로 남긴다**: 실제 발생(발견)시각 + 근거 · 보고 시각 + 입력 방식(즉시/사후) · 서버 기록시각(서버가 강제) · 휴대폰에서 누른 시각과 보낸 시각.

## 5. 기기 간 연동 검증 (로컬 · 브라우저 세션 3개)

`tests-pilot/e2e/cases.mjs` — 관리자 PC 화면(데스크톱) · 기사 A 휴대폰 화면 · 기사 B 휴대폰 화면이 각자 로그인한다.

| A가 보고하면 열어 둔 관리자 화면에 나타난다 (새로 고침 없이) | 통과 — 10초 확인 주기 안 |

| B 휴대폰에는 A의 일정 · 사건 · 안전점검이 보이지 않는다 | 통과 (RLS) |
| B는 관리자 화면과 증빙 내보내기에 들어갈 수 없다 | 통과 (화면 이동 · 403) |
| 연결이 끊긴 상태에서 보고 → 저장되지 않고 '다시 보내기'. 입력 내용은 남는다 | 통과 |
| 복구 뒤 다시 보내기 → 사건 1건만 저장 (중복 없음) | 통과 (같은 요청 번호 op_id) |
| 조치 이력이 순서대로, 중복 없이 저장된다 | 통과 |
| 해결된 사건은 '끝난 사건'으로 옮겨지고, B의 미처리 요청은 계속 보인다 | 통과 |

**자동 갱신 방식**: 화면이 보일 때 주기적으로 '변경 확인'(`/pilot/changes`, 내가 볼 수 있는 표의 최신 기록 시각)만 묻는다. 바뀌었을 때만 화면 자료를 다시 읽고, 바뀐 것이 없어도 60초마다 한 번은 다시 읽는다. 입력 중일 때는 8초 동안 다시 읽지 않아 입력 중인 화면이 흔들리지 않는다. 실시간 푸시가 아니므로 반영까지 최대 한 주기(관리자 10초 · 현장 15초)가 걸릴 수 있다.

**아직 하지 않은 것**: 서로 다른 실제 기기(PC 1대 + 휴대폰 2대 이상), 이동통신망, 실제 카메라 사진(시험은 화면 캡처 JPEG를 사진 파일로 사용), iPhone·Android 브라우저별 확인. 배포 승인 뒤 참여시험 가이드의 시험 A로 한다.

## 6. 안전점검 검증

| 확인 | 결과 |
|---|---|
| '미흡'을 고르면 프로그램 판단을 기다리지 말고 **작업 중지 · 본사에 직접 전화** 안내 | 통과 |
| 착용 사진 없이는 제출 불가 · 필수 항목(안전모 · 안전화 · 작업구역)은 '해당 없음' 불가 | 통과 |
| 사진이 있어도 자동 적합 아님 → 상태 '확인 대기' | 통과 |
| 미흡 항목이 있으면 관리자 '적합' 버튼 비활성 (DB 함수도 거절) | 통과 |
| 관리자가 점검 사진을 실제로 열어 봄 (비공개 저장소 서명 주소) | 통과 |
| 보완 요청 → A 휴대폰 도착 → 보완 제출(사진) → 본사 반영 → 조치 완료 · 이력은 추가만 | 통과 |
| '적합(육안 확인)' 결과가 A 휴대폰에 반영 · B에게는 A의 점검이 안 보임 | 통과 |

사진을 AI로 판단하지 않는다. 적합은 관리자 육안 확인 기록으로만 정해진다. 점검 항목 8개(필수 3)는 **초안**이며 회사 안전기준으로 확정해야 한다 (`src/lib/pilot/safety.ts`).

1. **실제 기기 · 현장 시험 미실시** — 운영 Supabase · Vercel 설정 승인 뒤 참여시험 가이드 시험 A부터 한다.

6. 안전점검 항목은 초안이다. 사진 자동 판정(AI)은 하지 않는다.
7. 측정 7(수기 vs AX)은 참가자 시험을 해야 값이 생긴다. 지금 화면에 있는 값은 시험 코드가 넣은 검증용 값이다.
8. R7(취소 일정 사이 이동 기준) 판단 보류는 그대로 유지한다 (`docs/PILOT_R7_CONFIRMATION_PROPOSAL.md`, 미구현 개선안).

### 10장 보충 — 최종 점검에서 고친 것 (`6abfa62`)
