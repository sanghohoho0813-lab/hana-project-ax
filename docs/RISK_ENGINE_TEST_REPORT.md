## 6. 비교실험 — 기존 정적 충돌 검사 vs 연쇄위험 엔진

- **기준 방식**: 기존 코드 `findConflicts()` (`src/lib/ops-calc.ts`, 이번 작업에서 수정하지 않음). 같은 담당자 인접 일정의 **예정 시간**만 비교.
- **개선 방식**: `evaluateChainRisk()` — 선행 예상 종료와 이동시간 반영, 연쇄 전파.
- 같은 시험 데이터에 두 방식을 함께 적용했습니다. 엔진의 '감지'는 판정 결과 '중간' 이상입니다.

> 이 결과는 **기존 코드 대비 기능검증**입니다. 외부 상용 CRM·일정관리 제품과 비교한 것이 아니며, 외부 제품 대비 우수성은 **별도 검증이 필요**합니다.

## 10. 검증 한계

- 시험 데이터는 **가상 시나리오와 데모 데이터**입니다. 실제 현장 운영데이터로 검증하지 않았습니다.
- 이동시간은 입력값·데모 가정값이며 실제 교통 상황을 반영하지 않습니다.
- 위험등급 기준(10분·30분), 확인 기준(120분), 우선순위 가중치는 설정값·**초기 운영 가정값**이며 현장 실증으로 정한 값이 아닙니다.
- 우선순위 점수는 관리자 판단 보조용이며 **확률이나 사고 발생률이 아닙니다**.
- 작업개시 지연에 따른 예상 종료는 '작업시간 유지' 가정의 규칙 기반 추정입니다.
- 업무 누락·일정 지연 감소 같은 **효과 수치는 측정하지 않았습니다**. 이 보고서에 성공률·개선율은 없습니다.
- 비교 대상은 같은 저장소의 기존 코드뿐이며, 외부 제품과의 비교는 하지 않았습니다.
- 판단 이력·상태이벤트 기록은 브라우저 메모리 기록이며 영구 저장·위변조 방지가 없습니다. 역할 전환은 데모 기능이며 서버 인증이 아닙니다.
- 화면 점검(8장)은 자동 테스트가 아니라 브라우저 조작 결과입니다.
- 특허 청구항 원문과의 대조는 하지 않았습니다 (`docs/PATENT_IMPLEMENTATION_MAPPING.md` 참고).
