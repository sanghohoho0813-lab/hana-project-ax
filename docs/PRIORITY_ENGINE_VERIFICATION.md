> **우선순위 점수는 관리자가 무엇부터 확인할지 정하도록 돕는 규칙 점수입니다. 사고 확률이나 실제 사고 발생률이 아니며, 통계적 타당성은 검증되지 않았습니다.**
> 가중치는 **초기 운영 가정값**이고 설정으로 바꿀 수 있습니다. 엔진은 일정을 바꾸지 않습니다. AI·기계학습을 쓰지 않습니다.

## 1. 설계 원칙

| 원칙 | 구현 |
|---|---|
| 결정적 | 같은 입력이면 항상 같은 점수·순서. 현재 시계를 읽지 않음 (기준시각은 인자) |
| 설정 가능 | 가중치 전부 `PriorityConfig`로 주입. 기본값 `DEFAULT_PRIORITY_CONFIG` |
| 안정적 동점 처리 | 점수 → 가장 이른 영향 현장 시작 → 항목 키 순 |
| 중복 계산 금지 | 같은 지연 출발점에서 나온 연쇄 위험은 한 항목. 각 후속 현장은 한 항목에만 들어감 |
| 판단 보류 분리 | 데이터가 부족한 연결은 점수 없이 '데이터 확인 대상'으로 따로 둠 (위험 없음이 아님) |
| 누락 데이터는 높게 평가하지 않음 | 값이 없는 요소는 0점 |
| 근거 공개 | 요소별 점수와 이유(`breakdown`)를 결과에 남기고 화면에 표시 |

## 2. 입력

- 연쇄위험 결과 `RiskResult` (`evaluateChainRisk`) — 연결별 상태·등급·부족분·원인·지연 출발 현장
- 기준시각 `asOf` (데모 `2026-07-28T10:40`, 검증 흐름은 단계별 고정값)
- 일정별 업무 우선순위 `SiteMeta` (일정의 `taskId`로 정확히 연결되는 업무만)
- 설정 `PriorityConfig` (없으면 기본값)

대상 연결: 상태 '판정'이고 등급 **중간 이상**. '주의'는 위험으로 세지 않고 `watch` 목록에만 둡니다.

## 3. 규칙

### P1 묶음 · 중복 방지
| 원인 | 묶음 키 | 항목 종류 |
|---|---|---|
| 시간 중복 | `link:<연결 키>` | 일정 중복 |
| 이동시간 부족 (예정값만으로 부족) | `link:<연결 키>` | 이동시간 부족 |
| 선행 현장 지연 · 연쇄 지연 | `root:<작업자>|<날짜>|<지연 출발 현장>` | 작업지연 위험 |

A현장 지연으로 B·C현장이 함께 위험해지면 **한 항목**(B현장 작업지연 위험, 영향 현장 B·C)이 됩니다. C현장이 다른 항목에서 다시 집계되지 않습니다.

### P2 점수

```
점수 = 위험등급 기본점수
     + 예상 지연 점수     = min(가장 큰 예상 지연, 상한) × 1분당 점수
     + 후속 현장 영향     = (영향 현장 수 − 1) × 1곳당 점수
     + 대응 시한 점수     = 가장 이른 영향 현장 시작까지 남은 시간 구간 점수
     + 업무 중요도 점수   = 영향 현장에 연결된 업무의 가장 높은 우선순위 점수
```

기본 설정값 (`DEFAULT_PRIORITY_CONFIG`, **초기 운영 가정값 — 실증 데이터로 정한 값 아님**)

| 요소 | 값 |
|---|---|
| 위험등급 기본점수 | 중간 20 · 높음 40 · 매우 높음 60 |
| 예상 지연 | 1분당 1점, 상한 60분 (한 요소가 점수를 독차지하지 않게) |
| 후속 현장 영향 | 첫 현장 외 1곳당 10점 |
| 대응 시한 | 30분 이내 15점 · 60분 이내 10점 · 120분 이내 5점 · 그 밖 0점. 기준시각이 다른 날이면 0점 |
| 업무 중요도 | 긴급 10점 · 보통 0점 · 낮음 0점 · **연결 업무 없음 0점** |

### P3 정렬 · 보류
1. 점수 내림차순
2. 동점이면 가장 이른 영향 현장 예정 시작이 빠른 순
3. 그래도 같으면 항목 키 사전순 (입력 순서와 무관)

판단 보류 연결 → `held` (점수 없음, 사유·권장 확인 포함). 주의 연결 → `watch`.

## 4. 출력 (`PriorityResult`)

`version`, `ruleVersion`, `asOf`, `config`(사용한 설정 전체), `items[]`, `held[]`, `watch[]`.

`PriorityItem`: `rank`, `key`, `kind`, `title`, `grade`(묶음 안 가장 높은 등급), `maxShortfall`, `root`(지연 출발 현장), `sites[]`(영향 현장별 예정 시작·부족분·등급), `earliestStart`, `minutesUntil`, `score`, `breakdown[]`(요소·값·점수·이유), `basis`(판단 근거 문장), `actions`(권장 확인, 중복 제거), `linkKeys`.

우선순위 변화 `diffPriority(before, after)` → 항목별 `신규 · 상승 · 하락 · 유지 · 해소`와 변경 전후 순위·점수.

## 8. 한계와 가정

- **가중치는 초기 운영 가정값**입니다. 현장 데이터로 정하거나 검증하지 않았습니다. 실증 후 조정 대상입니다.
- 점수는 **확률이 아닙니다**. 점수 차이를 위험 크기의 비율로 해석하면 안 됩니다.
- 업무 중요도는 기존 업무 우선순위(긴급·보통·낮음)만 씁니다. 고객 중요도·계약 조건·대체 인력 가용성은 데이터가 없어 반영하지 않았습니다.
- 대응 시한은 같은 날 기준시각에서만 계산합니다.
- 데모 화면의 우선순위는 데모 기준일(2026-07-28) 하루의 일정으로 계산합니다. 판단 이력은 변경된 일정의 날짜로 계산합니다. 여러 날을 함께 비교하지 않습니다.
- 판단 이력·우선순위 변화 기록은 브라우저 메모리에만 있습니다 (영구 저장·감사로그 없음).
- 이동시간은 입력값 또는 데모 가정값입니다. 실시간 교통정보가 아닙니다.
- 시험 데이터는 가상 시나리오와 데모 데이터입니다.
