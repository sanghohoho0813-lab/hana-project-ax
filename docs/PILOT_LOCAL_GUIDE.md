# 실증 프로그램 사용 가이드 (브라우저 저장판)

대상 기술: **복수 현장 업무 위험관리 AX 시스템** (연쇄위험 엔진 `chain-risk/1.1.0` · 상태편차 `state-deviation/1.0.0` · 우선순위 `response-priority/1.0.0` — 변경 없음)
목적: 하나정보통신에서 전달받은 현장정보를 직접 여러 번 입력·시험하면서, **출처와 측정방법이 분명한** 기술검증·전후 비교자료를 쌓는다.

> **중앙 DB 가 아닙니다.** 기록은 이 브라우저(localStorage)에만 저장됩니다. 다른 기기·다른 브라우저와 실시간으로 공유되지 않습니다.
> 브라우저 데이터를 지우면 기록이 사라질 수 있으니 **시험이 끝날 때마다 JSON 백업**을 받아 두세요. Supabase 연결은 보류 중입니다.

## 1. 빠른 사용 순서 (관리자 → 현장기사 모바일 입력 → PC 결과 확인 → 내보내기)

1. **실증 홈**(`/`)에서 **현장 실증 기록 시작**을 누른다.
2. **새 세트** — 데이터 구분을 고른다.
   - `실제 업무`: 오늘 실제로 일어나는 일을 바로 입력 (버튼 누른 시각 = 실제 시각)
   - `사후 재현`: 이미 지난 업무를 전달받은 정보·업무일지로 다시 입력 → **재현 기준시각(가정값)** 을 넣는다
   - `가상 시나리오`: 시험·연습용 가상 일정
   - 핵심 참여자(기본 구본석 이사)·기본 정보 제공자·자료 출처·원자료 이름을 적는다.
3. **관리자 시점**
   - 현장기사가 없으면 **시험용 기사 추가** (이름·코드).
   - **일정 등록**으로 현장 A·B·C 를 넣는다 (기사 · 현장 · 예정 시작·종료 · 직전 현장에서 이동시간). 이동 출발 현장은 그 기사의 바로 앞 일정으로 자동 기록된다. 폼이 열린 채로 남아 다음 현장을 바로 넣을 수 있다.
4. 화면 위쪽 **`[PC] [Mobile] [PC+Mobile]`** 에서 **PC+Mobile** 을 누른다 → 왼쪽 PC(관리자), 오른쪽 390px 휴대폰(현장기사).
5. 오른쪽 휴대폰에서 기사를 고르고 버튼을 누른다: **업무 확인 · 작업 시작 · 예상 종료시간 변경 · 작업 종료**.
   - 사후 재현·가상 세트는 버튼을 누르면 **실제 시각**을 묻는다. 모르면 **시각 모름** (추정해서 넣지 않음).
   - 틀렸으면 기록 옆 **정정** → 새 시각 또는 **잘못 누름 — 이 기록 무효**. 원래 기록은 지워지지 않는다.
6. 왼쪽 PC 에서 바로 결과를 본다: **위험 판단과 대응 우선순위**, **입력·조정할 때마다 판단 전 → 후** (계산 흐름 문장).
   - 예: `A현장 작업 시작 09:20(기록값) — 예정보다 20분 늦음` → `A현장 예상 종료 10:20(작업개시 지연 추정) + 이동 20분(입력값) → B현장 도착 10:40(계산값) / 예정 시작 10:30 → 10분 늦음 → 위험 높음` → `판단 변화: 신규 위험`.
7. 관리자가 **조정**(일정 시간 변경) 또는 **취소** → 다시 판단한 전후가 기록된다. 취소하면 후속 현장 이동 출발지·이동시간 재확인 안내가 뜬다 (R7 판단 보류 유지).
8. **실증 기록·내보내기**(`/records`)에서 **지금 JSON 백업 받기** · **CSV** (작업 기록 · 일정 등록·조정 · 위험 판단 전후 · 비교시험 측정 · 문제·피드백 · 실증 세트·회차).

**입력자** (화면 위쪽 `입력자: …`) 는 지금 프로그램에 입력하는 사람이다. 시험용 역할 전환이며 로그인이 아니다.
컨설턴트가 들은 내용을 넣으면 `입력자 컨설턴트 · 정보 제공 구본석 · 대리 입력`으로 남는다. 구본석 이사가 직접 누를 때는 입력자를 구본석으로 바꾼다.

## 2. 반복시험 (2~5일)

| 하고 싶은 것 | 방법 |
|---|---|
| 같은 일정으로 다시 시험 | 현장 실증 → **같은 일정으로 반복** (작업 기록은 비우고 일정만 복사 · 반복 회차 번호가 붙음) |
| 매일·회차 구분 | 세트·측정마다 `참가자 · 날짜 · N회차`가 자동으로 붙는다 (같은 참가자의 같은 날 반복) |
| 수기 vs AX 비교 측정 | **전후 비교시험**(`/compare`) → **새 측정 기록** → 앱 측정기 `1부 시작/끝` `조치 전달/2부 끝` → 발견 위험·놓친 위험·잘못 판단·후속 영향·재판단 시간 |
| AX 방식을 앱에서 풀기 | 현장 실증 → **비교시험 시나리오 불러오기** (A1~B5 · 연습 R1·R2 를 가상 시나리오 세트로) |
| 정답 위험 수 | 측정 입력의 **정답표 값** (기존 `trial/data/answer-key.json` 고정값 · 진행요원만) |
| 문제·수정사항·피드백 | 전후 비교시험 아래 **문제·수정사항·참여자 피드백** — 말한 사람과 `참여자가 직접 확인 / 미확인`을 함께 남김 |
| 결과보고서 | 기록·내보내기 → **보고서 정리 화면** (① 기간·참가자·횟수 ~ ⑦ 한계, 인쇄·PDF·Markdown) |

측정 기준은 `trial/TRIAL_PLAN.md` 5장과 같다. **측정하지 않은 값은 비워 두고**, 수기·AX 실측이 모두 있어야 비교값(중앙값 차이)을 낸다. ⑥ 향후 예상 효과는 사람이 쓰는 칸이며 '예상'으로 따로 표시된다.

## 3. 백업

| 상황 | 방법 |
|---|---|
| 시험이 끝날 때마다 | 홈 또는 기록 화면 **지금 JSON 백업 받기** — 파일 이름 `hana-ax-lab-backup-날짜-시각.json` |
| 백업 상태 확인 | 화면 위쪽 배지: `백업 안 함`(빨강) · `백업 뒤 변경 N`(주황) · `백업 HH:MM`(파랑) |
| 다른 PC·브라우저에서 이어 하기 | 기록 화면 **JSON 파일 고르기** → 파일 지문 일치 · 판단 재계산 일치 확인 → **이 백업으로 바꾸고 이어 하기** (지금 기록은 따로 한 칸에 보관) |
| 저장 실패·공간 부족 | 빨간 경고가 뜨고 방금 입력은 저장되지 않는다 → 바로 JSON 백업 |
| 저장된 기록 손상 | **손상된 원문 내려받기** → 백업 JSON 불러오기 (또는 새로 시작) |

백업 JSON 에는 `sha256`(파일 지문)이 들어 있어, 불러올 때 내용이 바뀌었는지 확인한다. 불러오면 모든 위험 판단을 저장된 입력으로 다시 계산해 저장된 결과와 같은지 확인한다.

## 5. 화면 보기 (PC · Mobile · PC+Mobile)

- **Same App · Same Route · Same Data** — 모바일 화면은 같은 앱의 같은 경로를 실제 390px(또는 430px) iframe 으로 띄운다. 축소 이미지가 아니라 그 폭의 반응형 화면이며, 같은 브라우저 저장소를 쓴다.
- **Frame 재귀 방지** — iframe 안에서는 보기 전환과 iframe 을 그리지 않는다.
- **Route 동기화** — PC 에서 메뉴를 옮기면 모바일도, 모바일에서 옮기면 PC 도 같은 경로로 간다. 경로가 같으면 아무것도 하지 않아 반복 이동이 없다. 시점(관리자/현장기사)은 창마다 고른다 (PC 기본 관리자 · 모바일 기본 현장기사).
- **데이터 동기화** — 한쪽에서 저장하면 브라우저 `storage` 이벤트로 다른 쪽이 다시 읽는다 (받는 쪽은 다시 쓰지 않음). 저장할 때마다 최신 저장값을 다시 읽고 바꾸므로 두 화면이 서로의 기록을 덮어쓰지 않는다.
- 실제 휴대폰으로 접속하면 같은 화면이 휴대폰 폭으로 보인다 (보기 전환 버튼 없음).
- 기존 Master MD 파일은 저장소·작업 환경에서 찾지 못해, 요청서에 적힌 규칙(위 4가지 + 모바일 QA)대로 구현했다.

## 7. 시험 실행 (개발자)

```bash
npm test                                     # 기존 자동 테스트 113개
npx vitest run --config trial/vitest.config.ts   # 비교시험 정답표 = 실제 엔진 (62)
npm run test:pilot                           # 실증 단위 시험 (54 — 로컬 실증 16 포함)
npm run build && npx next start -p 3197 &    # 화면 시험용 서버
npm run test:lab:e2e                         # 로컬 실증 12단계(49) + 기존 데모 회귀(37)
```

`npm run test:pilot:db` · `npm run test:pilot:e2e` 는 보류 중인 Supabase 판의 시험이다 (로컬 Supabase 필요).

## 8. 한계

- 한 브라우저 저장 — 여러 사람이 동시에 다른 기기에서 쓰는 운영 시스템이 아니다.
- 같은 브라우저의 두 탭에서 동시에 같은 순간 저장하면 드물게 한쪽이 늦게 반영될 수 있다 — 한 창(PC+Mobile 보기)에서 쓰는 것을 권장한다.
- 사후 재현·가상 시나리오의 판단은 재현 기준시각(가정값) 기준이다 — 실제 운영 효과가 아니다.
- 정답표 값은 화면 코드에 포함돼 있다 (진행요원 버튼으로만 표시).
