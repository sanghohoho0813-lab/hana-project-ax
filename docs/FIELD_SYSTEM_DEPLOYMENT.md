## 2. 운영에 필요한 인프라와 설정

### 2-1. Supabase — 새 프로젝트 1개 (승인 필요)

| 설정 | 값 | 비고 |
|---|---|---|
| 지역 | Northeast Asia (Seoul) | 현장·본사가 국내 |
| 스키마 | 마이그레이션 5개를 순서대로 적용 (`supabase/migrations/`) | 2개는 기존 실증판, 3개는 이번 추가분 |
| `seed.sql` | **운영 DB에 넣지 않음** | 로컬 개발용 서명키가 들어 있음 |
| 인증 | 공개 가입 끔 · TOTP 2단계 인증 켬 · Site URL = Vercel 주소 · Redirect URL = `https://<주소>/pilot/auth/confirm` | `config.toml`과 같게 맞춤 |
| 메일 양식 | 초대·비밀번호 재설정 양식 2개 (`supabase/templates/`) | 대시보드 Authentication → Email Templates에 붙여 넣음 |
| 판단 서명키 | `pilot_private.settings` 의 `judge_secret` = 32자 이상 무작위 값 | Vercel `PILOT_JUDGE_SECRET`과 같은 값 |
| 최초 관리자 | SQL 편집기에서 `select pilot_private.bootstrap_admin('관리자 이메일', '이름');` | DB 소유자만 실행 가능 |
| 사진 저장소 | `field-photos` (비공개, 10MB, JPEG·PNG·WEBP) — 마이그레이션이 만든다 | 공개 주소 없음 |
| 사진 보관기간 | `photo_retention_days` = 365 (기본값, 회사가 정함) | 3장 참고 |

**스키마 적용 방법 (하나를 골라 주세요)**
1. **소유자가 직접 실행 (권장)** — 회사 PC에서 `npx supabase login` → `npx supabase link --project-ref <프로젝트>` → `npx supabase db push`. DB 비밀번호가 저에게 오지 않습니다.
2. 대시보드 SQL 편집기에 마이그레이션 파일 5개를 이름 순서대로 붙여 넣어 실행.
3. 이 세션에서 실행 — 일회용 접근 토큰(Supabase Personal Access Token)과 DB 비밀번호가 필요합니다. 작업이 끝나면 토큰을 폐기해 주세요.

### 2-2. Vercel — 기존 프로젝트에 환경변수 4개 (직접 입력)

| 이름 | 값 | 노출 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소 | 브라우저에 보여도 됨 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Project Settings → API Keys 의 Publishable key | 브라우저에 보여도 됨 (RLS로 보호) |
| `NEXT_PUBLIC_PILOT_DB_LABEL` | 예: `실증 DB` | 화면 띠에 표시 |
| `PILOT_JUDGE_SECRET` | 2-1의 판단 서명키와 같은 값 | **서버 전용** (Sensitive로 저장) |

- 입력한 뒤 다시 배포(Redeploy)해야 반영됩니다. 프로그램 버전의 커밋은 Vercel이 자동으로 넣습니다(`VERCEL_GIT_COMMIT_SHA`).
- **Supabase 관리자 키(service_role / secret)는 Vercel에 넣지 않습니다.** 앱은 로그인한 사용자 권한으로만 DB를 씁니다.
- 환경변수가 없으면 `/pilot` 만 '설정 안 됨'으로 보입니다. 기존 데모·브라우저 저장판 화면은 그대로 동작합니다.

**권장: Supabase Pro ($25/월~) + Vercel은 지금 쓰는 플랜 유지.**
- 실제 업무 기록과 현장 사진이 들어가므로 일일 백업이 필요합니다. 주말이나 휴가 중 1주 무활동으로 일시 정지되면 현장에서 접속할 수 없습니다.
- Free로 짧게(1~2주) 시험할 수도 있습니다. 이때는 백업이 없으므로 매일 CSV·JSON 내보내기로 보관해야 하고, 무활동 일시 정지에 주의해야 합니다.

**사진 용량 가정 계산 (실측 아님)** — 사진은 휴대폰에서 긴 변 1600px JPEG로 줄여 올립니다. 1장을 0.4MB로 가정하면 기사 10명 × 하루 5장 × 22일 ≈ 월 440MB입니다. Free의 1GB는 2~3개월이면 찹니다. Pro의 100GB는 이 가정으로 수년 분량입니다. 실제 1장 크기는 첫 현장 시험에서 측정해 다시 계산합니다(사진마다 크기가 기록됨).

### 2-4. 권한 — 누가 무엇을 할 수 있나

| 역할 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| **DB 소유자** (회사 담당자 1명) | Supabase 대시보드, 스키마 적용, 서명키 설정, 최초 관리자 지정, 계정 초대, 백업·복구, 보관기간 변경 | — |
| **본사 관리자** (활성 + TOTP 2단계 인증 필수) | 계정 활성화·역할 변경, 모든 일정·사건·사진·안전점검 열람, 접수·배정·조치·일정 조정·해결 확인, 안전 육안 확인·보완 요청, 사진 삭제(사유 필수), 측정 입력, 증빙·CSV 내보내기 | 기록 고치기·지우기 (정정·무효는 새 기록을 추가하는 방식) |
| **현장기사** (활성 계정) | **본인** 일정·사건·안전점검·사진·의견만 보고 기록 | 다른 기사 자료 보기, 관리자 화면, 증빙·CSV 내보내기 (403), 사진 삭제 |
| **서버 (Vercel)** | 로그인한 사용자의 세션으로 DB 함수 호출 · 서명키로 판단 대기열 1건 읽기·판단 기록 | 관리자 키 없음 → RLS를 건너뛸 수 없음 |

권한은 화면이 아니라 **DB(RLS·함수·저장소 정책)** 에서 막습니다. 화면을 우회해 직접 요청해도 같은 규칙이 적용됩니다. 기사 B가 기사 A의 자료를 볼 수 없는지는 DB 시험과 화면 시험으로 확인했습니다 (`docs/FIELD_SYSTEM_0.3.md` 5장).

## 3. 현장 사진 — 접근권한 · 저장기간 · 삭제기준

현장 사진에는 사람 얼굴, 차량번호, 고객 시설 내부, 서류·화면 속 개인정보가 들어갈 수 있습니다. 그래서 아래 기준으로 저장합니다.
**(확정 필요)** 수집 목적, 보관기간, 근로자 고지·동의 방식은 회사의 개인정보 처리 기준과 법률 검토로 확정해 주세요. 아래는 프로그램이 지금 지키는 기술 기준입니다.

### 3-1. 저장되는 것

| 항목 | 내용 |
|---|---|
| 사진 파일 | 휴대폰에서 긴 변 1600px JPEG로 다시 저장. 이때 **촬영 정보(EXIF: 위치·기기 등)가 빠집니다**. 줄이지 못하는 형식이면 원본을 올리고 '원본(위치 정보가 남을 수 있음)'으로 표시합니다 |
| 기록 | 올린 사람 · 사건/안전점검 · 서버 기록시각 · 파일 지문(SHA-256) · 크기 · 촬영정보 제거 여부 · 보관 기한 · 프로그램 버전 |
| 저장 위치 | Supabase 비공개 저장소 `field-photos/{올린 사람}/{사건 또는 safety-점검}/{번호}.jpg`. 공개 주소가 없습니다 |

### 3-2. 접근권한 (DB 저장소 정책으로 강제)

| 동작 | 현장기사 | 관리자 |
|---|---|---|
| 올리기 | 본인 폴더, 본인 사건·점검에만 | — (현장기사가 올림) |
| 보기 | 본인이 올린 사진, 본인 사건의 사진 | 전체 |
| 덮어쓰기 | 불가 (같은 이름은 거절) | 불가 |
| 삭제 | 불가 | 사유를 넣어야 가능 |

- 화면은 사진을 **10분짜리 서명 주소**로만 엽니다. 주소를 복사해 두어도 10분 뒤에는 열리지 않습니다.
- 사건 증빙 JSON에는 서명 주소를 넣지 않고 파일 지문만 넣습니다. 파일이 바뀌지 않았는지는 지문으로 확인합니다.

### 3-3. 저장기간

- 기본 **작업일 + 365일** (`retain_until`). 사진마다 '보관 YYYY-MM-DD까지'가 증빙 화면에 보입니다.
- 회사가 기간을 정하면 `pilot_private.settings` 의 `photo_retention_days` 를 바꿉니다. 바꾼 뒤에 올리는 사진부터 적용됩니다.

### 3-4. 삭제기준과 방법

| 삭제 사유 | 예 |
|---|---|
| 보관 기한 경과 | 증빙 화면의 보관 기한이 지난 사진 |
| 개인정보·민감정보 노출 | 업무와 무관한 얼굴, 차량번호, 고객 서류, 화면 속 개인정보 |
| 잘못 올린 사진 | 다른 현장, 업무와 무관한 사진 |
| 요청·계약 종료 | 촬영된 사람의 요청, 고객사 요청, 실증 계약 종료 |

- 삭제는 **관리자만**, **사유를 넣어야** 할 수 있습니다. 저장소의 파일은 지워집니다. 기록 행(지문·삭제 사유·삭제자·시각)은 남아 '언제 왜 지웠는지'가 증빙으로 남습니다.
- **지금 한계**: 보관 기한이 지나도 자동으로 지우지 않습니다. 관리자가 보관 기한을 보고 사유 '보관 기한 경과'로 지웁니다. 자동 삭제가 필요하면 예약 작업(추가 설정)으로 후속 구현합니다.

### 3-5. 현장기사 촬영 안내 (화면 안내와 교육에 사용)

- 작업 부위, 장비, 배선, 안전장비 착용 상태 위주로 찍습니다.
- 사람 얼굴(본인 외), 차량번호, 고객 서류·모니터 화면은 화면에 들어가지 않게 찍습니다.
- 안전 위험이 보이면 사진보다 먼저 **작업을 멈추고 본사에 전화**합니다. 프로그램은 사진으로 자동 판단하지 않습니다.
