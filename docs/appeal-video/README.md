# 소개 영상 — 복수 현장 업무 위험관리 AX 시스템

**현재판: 3판 (2026-11-26)**
- 길이 6분 57초 · 1920×1080 · 60fps
- 음성: 새 녹음 1.08배속, -14 LUFS
- 제작 도구는 `v3/`에 있다.

1판·2판 도구는 `src/`에 있다. 1·2판은 밝은 배경에 문장 단위 자막이었다.

영상 파일(mp4)은 용량 때문에 저장소에 넣지 않고 사용자에게 직접 전달했다. 자막은 `narration.srt`이다.

## 3판에서 바꾼 것 (사용자 지적 반영)

### 1. 채널 스타일로 통일
기준은 사용자의 '영상 도구 · 스타일 통합 가이드 V1.1', 유튜브 v1.2, AX v4.1이다.
- **배경**
  - 기본: 남색·차콜에 금빛·청록 빛, 90px 격자
  - 자료·계산 장면: 따뜻한 아이보리
  - 정리 장면: 슬레이트
  - 장 표지: 시드를 고정한 흐름선 배경(왼쪽 청록 → 오른쪽 금, 가운데는 어둡게)
- **색**: 금(메인) + 청록(보조) 한 계열이다. 빨강은 '부족 · 사고' 같은 경고에만 쓴다.
- **글꼴과 크기**: Pretendard. 제목 62px, 큰 제목 96~104px, 칩 42px.
- **움직임**
  - 튕김, 크기 팝, 깜빡임은 쓰지 않는다.
  - 글자는 0.18초 안에 다 밝아지고 26px 올라온다.
  - 카메라 이동은 quintInOut이고, 위치는 정수 px로 맞춘다.

### 2. 자막을 짧게
- 대본을 숨 단위 187조각으로 나눴다. 한 줄 최대 27자이고, 24자를 넘는 조각은 4개뿐이다.
- 조각의 44%에 핵심어를 **금색 굵게** 표시했다. 강조는 최대 4개까지만 연속된다.
- 자막 글자는 대본 그대로이고, 시각만 녹음에서 가져왔다.
  - 대본과 녹음의 글자 일치율은 98.4%이다.
  - 모든 조각이 0.9초 이상 표시된다.
- 자막 모양: 52px, 700 굵기. 반투명 둥근 상자에 넣고, 화면 아래에서 68px 띄운다.

### 3. 인포그래픽이 잘리던 문제
- 그림 전체(아래 띠 포함)가 자막 위에 들어오도록 크기와 위치를 다시 잡았다.
- "다음 현장 일정 자동 조정" 덮개의 기준을 그림 자체로 바꿨다.
  - 1·2판은 그림과 설명을 합친 높이를 기준으로 잡아, 덮개가 어긋나고 원래 글자("다음 혀잔")가 비쳤다.
  - 이제 "다음 현장 일정 / 조정 후 재계산"으로 정확히 덮는다.
- '회사 개념 그림' 표시는 그림 바깥 위쪽으로 옮겼다.

### 4. PC 화면의 여백
- PC 화면은 원본 전체(1080×675)를 브라우저 틀에 넣고, 필요한 곳만 천천히 당겨 보인다.
- 틀은 화면 폭 1000~1400px이고 위 막대(점 3개 + 주소칸)가 있다.
- 바짝 잘라낸 조각을 쓰지 않으므로 페이지 여백과 메뉴가 그대로 보인다.

### 5. 휴대폰을 실제 기기처럼
- 휴대폰은 390×844 원본 화면을 통째로 넣은 실제 기기 비율(9:19.5) 틀이다.
  - 테두리 14px, 모서리 54px, 위쪽 섬 모양(다이내믹 아일랜드)
- PC와 같이 나올 때는 화면 폭 290~300px, 3대를 나란히 둘 때는 262px이다.
- 모든 기기 틀은 자막 위(y 890 이내)에서 끝난다.

### 6. 실제 기능 위주 + 자료가 없는 곳만 효과 장면
- **실제 화면**
  - 화면 위의 금색 번호 테두리는 실제 요소 위치에 얹었다.
    - 휴대폰: 촬영 때 잰 위치를 원본 좌표로 옮겼다(`cropmap.py`).
    - PC: 원본 화면에 격자를 그려 직접 쟀다.
  - 커서 클릭(물결)과 손가락 누름 표시가 들어간다.
  - 같은 틀 안에서 화면이 바뀐다: 지원 결정 → 현장 전달, 보완 요청 → 조치 완료, 조정 입력 → 재판단.
- **효과 장면**(가이드에서 심사용으로 적절한 것만 골랐다)
  - 흐름선 장 표지
  - 계산 타임라인: 보령 → 홍성 → 예산
    - 실제 계산값(13:00 + 20분 = 13:20 → 50분 부족 → 45분 부족)이 막대 위치를 정한다.
    - '실제 프로그램 계산값 · 검증 시나리오'로 표시했다.
  - 계단 흐름(비용 증가), 개념도(본사 1곳 ↔ 현장 여러 곳)
    - '설명용 개념도'로 표시했다.
  - 성과 시간축: 월 단위 비례, 746 숫자 세기, 2027년 초는 점선·'목표'로 표시
  - 적용 산업 허브

## 표시 원칙
- 프로그램 화면은 모두 실제 화면이다. 사람·현장 이름과 일정은 검증 시나리오(시험용)이고, 계산 숫자는 프로그램이 낸 값이다.
- 사진에는 '회사 제공 사진' / 'AI 연출 사진' 표시를 붙였다.
- 계획(2027년 초 정식 운영, 적용 산업 확대, 현장 데이터 고도화)은 '목표 · 계획'으로 표시했다.
- 우선순위 점수는 '규칙 기반 점수 (AI 예측 아님)'로 적었다.

## 다시 만들기 (`v3/`)
입력 파일은 세션 작업 폴더에 있다: 녹음, 촬영본 `appeal/final`, 전체 화면 `vid/full`, 회사 사진 `vid/ref`.

1. **녹음 준비**
   - 새 녹음을 1.08배속(`atempo=1.08`)으로 바꾼다.
   - 끝의 요청 문장을 자른다(414.8초).
   - 앞에 0.6초 무음을 넣는다.
   - 2-pass loudnorm으로 -14 LUFS, 최대 -1.5dB에 맞춘다.
2. **받아쓰기**: faster-whisper로 단어 시각을 얻는다(`../src/asr.py`).
3. **자막 조각 맞추기**: `chunks.txt`(한 줄에 자막 하나, `**핵심어**`) → `subs3.py`
   - 결과: `subs.json` · `subs.srt` · `timing.json`(장면 앵커)
   - 대본과 글자 하나라도 다르면 멈춘다.
4. **번호 위치 옮기기**: `cropmap.py` → `screens.json`(휴대폰 촬영본의 번호 위치를 원본 좌표로)
5. **흐름선 배경**: `node flowbg.mjs 47 7 21` → `bg/flow_*.jpg`
6. **장면 만들기**: `scenes3.py`(장면, `K("대본 문구")` 시각 앵커) → `player.html` · `timeline.json`
   - 점검: `../src/check_timing.py player.html`
7. **렌더**: `node render.mjs video out.mp4 60 4`
   - 프레임마다 `seek(t)` → x264 crf17 → 녹음 합성(aac 192k)
