# 소개 영상 — 복수 현장 업무 위험관리 AX 시스템 (2026-11-26 · 6분 57초 · 1920×1080)

사용자가 준 대본 녹음에 실제 프로그램 화면을 문장 단위로 맞춘 영상이다.

- 2판(2026-11-26): 사용자가 밝은 목소리로 다시 녹음한 파일(7분 35초)을 썼다.
  - 1.08배속으로 바꿨다(음높이 유지, ffmpeg `atempo=1.08`).
  - 녹음 끝에 대본이 아닌 요청 문장("이 대본으로 해서 영상 새로 하나 만들어줘…")이 읽혀 있어 잘라냈다. 영상은 "…AX 시스템입니다."에서 끝난다.
  - 새 녹음에는 "세 번째 문제, 복수 현장의 연쇄적인 작업 지연." 한 줄이 더 있다. 문제 ③ 제목 화면을 이 문장에 맞췄다.
- 1판(2026-11-25): 첫 녹음(7분 18초) · 7분 20초.
- 영상 파일(mp4)은 용량 때문에 저장소에 넣지 않았다. 사용자에게 직접 전달했다.
- 자막은 `narration.srt`에 있다.

## 화면과 표시 원칙
- 프로그램 화면은 모두 실제 화면이다.
  - 출처 1: 2026-11-22 11:00 시작 핵심 사례 촬영본 41장
  - 출처 2: 판단 기록 상세·사건 상세·기록·안전관리를 2배 해상도로 찍은 전체 화면
  - 화면 위의 빨간 테두리·번호와 누름 표시는 촬영할 때 잰 실제 요소 위치에 얹었다.
  - 스크롤 장면은 실제 화면 전체 캡처를 카메라처럼 움직인 것이다.
- 사람·현장 이름과 일정은 시험용이다(검증 시나리오). 계산 숫자는 실제 프로그램이 낸 값이다.
- 사진에는 표시를 붙였다.
  - '회사 제공 사진': 사용자가 준 최종검토본 PDF에서 꺼낸 현장 사진이다.
  - 'AI 연출 사진': 기존 연출 사진이다.
  - '회사 개념 그림': 회사가 만든 인포그래픽이다.
- 인포그래픽의 "다음 현장 일정 자동 조정" 문구는 "조정 후 재계산"으로 덮어 썼다. 프로그램은 일정을 스스로 바꾸지 않는다.

## 다시 만들기 (`src/`)
1. `asr.py` — 녹음을 받아써(faster-whisper small) 단어별 시각을 얻는다.
   - 무음 구간: `ffmpeg -af silencedetect=noise=-38dB:d=0.28` 출력을 `sil.txt`로 저장한다. 문장 시작·끝은 가까운 무음 경계에 맞춘다.
   - 첫 문장은 녹음이 무음으로 시작할 때만 무음 끝에 맞춘다. 1판은 무음 목록을 읽을 때 첫 무음 시작 줄이 빠져, 첫 문장이 3.6초에 시작하는 것으로 잘못 잡혔다. 2판에서 고쳤다.
   - `asr_align.py <1판 asr.json> <새 받아쓰기> asr.json` — 새 녹음의 받아쓰기를 기존 55문장 구분에 글자 단위로 맞춘다. 단어 글자는 그대로 두고 시각만 바꾼다. 기존에 없던 말은 `asr_extra.json`에 따로 남긴다(2판 글자 일치 98.8%).
2. `fullshots.mjs` — 실제 화면 전체를 2배 해상도로 찍고 제목 위치를 기록한다.
   - 로컬 Supabase와 서버가 필요하다.
   - 사례 날짜는 2026-11-22이다.
3. `make_player.py` — 장면, 단어 시각, 자막을 묶어 `player.html`, `timeline.json`, `narration.srt`를 만든다.
4. `check_timing.py player.html` — 장면 밖에서 나타나는 요소, 뒤집힌 창, 카메라 순서를 점검한다(2판 이상 0건).
5. `render.mjs video <out.mp4> 30 3` — 프레임마다 `seek(t)`로 화면을 그린 뒤 녹음과 합친다.
   - 프레임 → x264 crf17 → 녹음 합성(aac 192k)
   - 미리보기는 `render.mjs shots <폴더> 초 …`로 뽑는다.

입력 파일은 저장소 밖(세션 작업 폴더)에 둔다.
- 녹음 `narration.wav` (2판: 원본 → 1.08배속 → 414.8초에서 자름)
- 촬영 폴더 `appeal/final` · `appeal/extra`
- 회사 사진 `ref/`
