# 소개 영상 — 복수 현장 업무 위험관리 AX 시스템 (2026-11-25 · 7분 20초 · 1920×1080)

사용자가 준 대본 녹음(7분 18초)에 실제 프로그램 화면을 문장 단위로 맞춘 영상이다.
- 영상 파일(mp4)은 용량 때문에 저장소에 넣지 않았다. 사용자에게 직접 전달했다.
- 자막은 `narration.srt`에 있다.

## 구성
| 시각 | 장면 |
|---|---|
| 0:00 | 도입 — 1990년 사업 시작 · 2002년 면허 · 공공기관·학교 유지보수 (회사 제공 현장 사진) |
| 0:14 | 반복된 세 가지 문제 → 전화·수기가 아닌 기술로 → 시스템 소개 |
| 0:42 | ① 현장 지원 요청의 지연 |
| 2:08 | ② 현장 안전 확인의 누락 |
| 3:47 | ③ 복수 현장의 연쇄적인 작업 지연 (핵심 기술) |
| 6:04 | 기술개발 성과 · 향후 방향 · 적용 산업 확대 · 마무리 |

① 장면의 흐름:
1. 30분째 휴대폰이 먼저 묻기
2. 버튼 6번 보고
3. 우선 확인
4. 지원 결정 → 현장 전달

② 장면의 흐름:
1. 작업 전·중·후 점검
2. 착용 사진
3. 시작 전 확인
4. 1순위 표시
5. 보완 요청 → 재확인

③ 장면의 흐름:
1. 보령 → 홍성 → 예산 계산: 13:00 + 20분 = 13:20 → 50분 부족 → 예산 45분 부족
2. 우선순위 130점
3. 1·2차 조치 후 재계산: 위험 연결 2 → 1 → 0

## 화면과 표시 원칙
- 프로그램 화면은 모두 실제 화면이다.
  - 출처 1: 2026-11-22 11:00 시작 핵심 사례 촬영본 41장
  - 출처 2: 판단 기록 상세·사건 상세·기록·안전관리를 2배 해상도로 찍은 전체 화면
  - 화면 위의 빨간 테두리·번호와 누름 표시는 촬영할 때 잰 실제 요소 위치에 얹었다.
  - 스크롤 장면은 실제 화면 전체 캡처를 카메라처럼 움직인 것이다.
- 사람·현장 이름과 일정은 시험용이다(검증 시나리오). 계산 숫자는 실제 프로그램이 낸 값이다.
- 사진에는 표시를 붙였다.
  - '회사 제공 사진': 사용자가 준 최종검토본 PDF에서 꺼낸 현장 사진이다.
  - 'AI 연출 사진': 기존 연출 사진이다.
  - '회사 개념 그림': 회사가 만든 인포그래픽이다.
- 인포그래픽의 "다음 현장 일정 자동 조정" 문구는 "조정 후 재계산"으로 덮어 썼다. 프로그램은 일정을 스스로 바꾸지 않는다.

## 다시 만들기 (`src/`)
1. `asr.py` — 녹음을 받아써(faster-whisper small) 문장별 시각을 얻는다.
   - 첫 문장은 무음 구간 기준으로 보정한다.
   - 결과: `asr.json`
2. `fullshots.mjs` — 실제 화면 전체를 2배 해상도로 찍고 제목 위치를 기록한다.
   - 로컬 Supabase와 서버가 필요하다.
   - 사례 날짜는 2026-11-22이다.
3. `make_player.py` — 장면, 단어 시각, 자막을 묶어 `player.html`, `timeline.json`, `narration.srt`를 만든다.
4. `render.mjs video <out.mp4> 30 3` — 프레임마다 `seek(t)`로 화면을 그린 뒤 녹음과 합친다.
   - 프레임 → x264 crf17 → 녹음 합성(aac 192k)
   - 미리보기는 `render.mjs shots <폴더> 초 …`로 뽑는다.

입력 파일은 저장소 밖(세션 작업 폴더)에 둔다.
- 녹음 `narration.wav`
- 촬영 폴더 `appeal/final` · `appeal/extra`
- 회사 사진 `ref/`
