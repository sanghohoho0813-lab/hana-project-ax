같은 데이터 비교 시험

기존 ‘겹침 검사’와 연쇄위험 엔진에 같은 일정을 넣어 봤습니다

일정표 프로그램이 흔히 하는 ‘예정 시간 겹침 검사’를 같은 저장소의 기존 코드(findConflicts)로 돌려 엔진과 비교했습니다. 외부 상용 제품과의 비교가 아닙니다.

왜 차이가 나나

겹침 검사는 예정 시간만 비교하므로, 예정이 겹치지 않으면 앞 현장이 늦어져도 아무것도 찾지 못합니다. 엔진은 보고된 예상 종료 + 이동시간으로 계산하므로 ‘예정만으로는 보이지 않는 위험’을 찾습니다.

지연 크기별앞 현장 종료를 5분씩 늦출 때 — 엔진은 단계적으로, 겹침 검사는 끝까지 0구현 확인

이 시스템만의 계산 원리 6가지 + 안전 결합

1~6은 특허출원 기술구성과 연결되는 핵심 원리입니다(07 연계표). ‘+’는 현장 인터뷰로 더한 현장 보조 기능입니다.

#원리기존 방식이 시스템
1상태이벤트로 예상 종료를 다시 정함예정 종료를 그대로 믿음기사의 ‘예상 종료 보고’ · 작업개시 지연을 받아 앞 현장 종료를 다시 정함(R2). 무엇을 근거로 정했는지 표시
2시공간 제약으로 다음 현장 도착을 계산예정 시간이 겹치는지만 봄예상 종료 + 이동 필요시간 = 예상 도착, 여유 · 부족(분) · 5단계 등급(R3 · R4)
3연쇄 전파바로 다음 현장만 보거나 사람이 계산늦게 시작한 현장의 종료를 다시 정해 그다음 연결까지 이어서 계산(R5)
4모르면 판단 보류데이터가 없으면 ‘문제 없음’으로 보임이동시간 누락 · 취소 · 시각 오류는 ‘위험 없음’이 아니라 ‘확인 필요’로 분리(R7)
5근거 공개형 우선순위알림 순서가 불투명하거나 사람 감요소별 점수(등급 · 지연 · 영향 현장 · 시한 · 중요도), 같은 연쇄는 한 번, 동점 순서 고정
6조치 후 재판단 · 판단 기록조치 효과를 따로 확인하지 않음관리자 조치마다 같은 규칙으로 재계산, 전후 · 규칙 버전 · 지문(SHA-256) · 재계산 확인을 추가 기록
+안전점검과 작업 흐름의 결합점검표가 작업과 따로 놂점검 없이 시작 · 종료하면 먼저 묻기, 미흡이면 작업 중지 안내 · 본사 1순위, 관리자 육안 확인 기록
