## 표시 원칙
- 화면은 모두 실제 프로그램(v0.6.1 · 커밋 c74484c)을 로컬에서 조작해 찍은 것이다. 사람 · 현장 이름과 일정은 시험용이다(검증 시나리오, 사건 HT-20261122-001).
- 회사가 보낸 인포그래픽 8장은 ‘회사 개념 그림’으로 표시했다. 사실과 다른 문구는 바로잡았다:
  - ‘다음 현장 일정 자동 조정’ 칸은 그림 위에 ‘조정 후 재계산’을 덮어 썼다. 프로그램은 일정을 스스로 바꾸지 않는다.
  - ‘실시간으로 연결’ 문장이 있는 머리 부분은 잘라 냈다. 자동 갱신은 주기 확인 방식이다.
- 사진은 기존 AI 연출 사진 7장(뒷모습 · 옆뒷모습)이다. 정면 얼굴은 없다.
- 현장 실증은 0건이다. 측정하지 않은 효과 수치는 넣지 않았다. ‘계산 예시’ · ‘계획’ · ‘회사 기재(노란 칸)’를 표시로 나눴다.
- 외부 근거는 원문을 확인한 30건만 썼다. 출처는 `RESEARCH_SOURCES.md`에 있다.

## 다시 만들기
```bash
# (선택) 화면 다시 찍기 — 로컬 Supabase · next start -p 3197 실행 중
APPEAL_P=11:00 APPEAL_OUT=<촬영폴더> node tests-pilot/e2e/appeal-shots.mjs       # 핵심 사례 41장 (약 45분)
python3 docs/appeal-sample/facts.py <촬영폴더>/facts.json
APPEAL_OUT=<추가폴더> APPEAL_DATE=<촬영 날짜> node tests-pilot/e2e/appeal-extra-shots.mjs   # 판단 기록 상세 · 기록 · 비교 화면
# 문서 · PDF (촬영 폴더가 없으면 assets/shots/ 의 이미 잘라 둔 화면을 그대로 쓴다)
APPEAL_CAP=<촬영폴더> APPEAL_XCAP=<추가폴더> python3 docs/appeal-package/src/build.py [00 01 …]
node docs/appeal-package/src/render.mjs [00 01 …]     # 쪽 넘침 · 그림 누락 점검 포함
```
- 새 사진은 `assets/photos/new/P-xx.jpg`로 넣는다. 칸 번호는 `INTERNAL_PHOTO_GUIDE.md`를 본다. 실제 현장 사진이면 `P-xx.real`을 같이 둔다.
- 다시 빌드하면 자동으로 바뀐다.
