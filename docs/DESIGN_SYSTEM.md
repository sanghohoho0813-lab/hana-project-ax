# 하나 AX 디자인 시스템 (0.4.0 · UI/UX 개편)

목표: 현장기사는 교육 없이 한 손으로, 본사 관리자는 여러 현장의 위험과 조치를 한눈에 파악한다.
참고한 방향은 두 가지다. 특정 서비스의 화면을 복제하지 않고, B2B 현장업무에 맞게 다시 설계했다.
- 여백이 넉넉한 미니멀 카드형 화면
- 선명한 주요 버튼 · 하단 탭 · 상태 칩

## 1. 색 (globals.css `@theme`)

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `primary` | `#4F46E5` (인디고) | **포인트 색 1개** — 주요 버튼 · 선택 · 링크 · 진행 중 |
| `primary-dark` / `primary-light` | `#3730A3` / `#EEF0FF` | 눌림 · 연한 배경 |
| `bg` | `#F5F6F8` | 화면 바탕 (밝은 회색) |
| `surface` | `#FFFFFF` | 카드 |
| `ink` / `ink-2` / `ink-3` | `#111318` / `#4B5563` / `#6B7280` | 본문 · 보조 · 설명 (흰 바탕 명도 대비 4.5:1 이상) |
| `line` | `#E7E9EE` | 구분선 (테두리는 꼭 필요할 때만) |
| `danger` · `danger-bg` | `#DC2626` · `#FEF2F2` | **위험** — 위험 등급 중간 이상 · 안전 위험 · 미접수 긴급 |
| `warning` · `warning-bg` | `#B45309` · `#FFF7E6` | **주의** — 보완 요청 · 확인 대기 · 전송 대기 |
| `success` · `success-bg` | `#15803D` · `#ECFDF3` | **정상·완료** — 해결 · 적합 · 위험 해소 |
| `info` · `info-bg` | `#4F46E5` · `#EEF0FF` | 진행 중 (포인트 색과 같음) |
| 시험 데이터 | 점선 · 회청색 `#475569` / `#F1F5F9` | 가상 시나리오 · 검증 시나리오 (실제 기록과 늘 구분) |

상태 색은 뜻으로만 쓴다. 포인트 색으로 위험을 표시하지 않는다.

## 2. 모양 · 크기

- 모서리: 카드 20px · 버튼 14px(현장 16px) · 칩 완전 둥글게 · 하단 시트 위쪽 24px
- 그림자: 카드 1단계(아주 옅게) · 시트·모달만 진하게. 테두리보다 여백과 배경색으로 구분한다.
- 터치: 현장기사 주요 버튼 높이 56px 이상, 그 밖의 누르는 곳 44px 이상
- 글자 (실증 화면)
  - 현장(모바일): 본문 16~17px · 카드 제목 20~22px · 주요 버튼 18px 굵게
  - 관리자(PC): 본문 15~16px · 보조 13~14px · 화면 제목 26px
- 간격: 4px 단위 (카드 안 16~20px · 카드 사이 12~16px · 구역 사이 24~32px)

## 5. 문구

- 짧게 쓴다: 한 줄 안내 + 필요하면 '자세히' 펼쳐보기
- 행동 버튼은 동사로 쓴다: "작업 시작", "보고 보내기", "접수"
- 시험 데이터 · 실제 업무 · 실제 과거 현장정보 재현을 늘 구분한다. 확인하지 않은 효과나 실증 완료를 쓰지 않는다

## 6. 화면 규칙

- 현장기사 화면: 맨 위 **지금 할 일** → 오늘 요약 → 본사에서 온 소식 → 방문 순서. 주요 버튼(작업 시작 · 작업 종료)은 **아래 고정**한다.
- 저장 결과는 같은 모양(`Notice` · 아래 알림)으로 보여 준다: 무엇이 · 언제(실제 시각 · 서버 기록) · 어떻게(입력 방식).
- 확인창은 되돌릴 수 없는 일에만 쓴다(사진 파일 삭제 등). 잘못 누른 기록은 지우지 않고 '잘못 누름 · 시각 정정'으로 덧붙인다.
- 표는 모바일에서 표 안에서만 가로로 밀린다(`table-scroll`). 화면 전체가 가로로 넘치지 않게 한다.
- 데이터가 없을 때는 `Empty`로 이유와 다음 행동을 쓴다.
- 인쇄 증빙(사건 증빙 · 판단 기록)은 화면 개편과 따로 둔다. 화면 전용 부품은 `print:hidden`.
