## 2. 발명의 명칭 용어와 현재 구현의 관계 (참고)

청구항 원문이 없으므로, 명칭에 쓰인 용어가 코드에서 무엇에 해당하는지만 정리합니다. **용어 대응이지 청구항 대조가 아닙니다.**

| 명칭의 용어 | 현재 코드에서 해당하는 것 | 비고 |
|---|---|---|
| 복수 현장 프로젝트 | 여러 프로젝트·현장의 일정(`ScheduleItem`, `projectId`, `region`) | |
| 작업상태 이벤트 | 업무 상태 변경(확인·시작·보고·검토), 일정 상태 변경, 예상 종료 입력 | 판단 이력의 `RiskEvent` 로 기록 |
| 시공간 제약정보 | 예정 시작·종료(시간), 이동 필요시간(공간 간 이동) | 위치 좌표·지도 정보는 없음 |
| 연계업무 위험도 산출 | 같은 작업자 연결의 여유·부족과 위험등급, 연쇄 전파 | 규칙 기반 (`chain-risk/1.0.0`) |
| 대응 우선순위 결정 | 위험등급, 권장 확인 항목, 알림 심각도 정렬 | 통합 우선순위 점수는 미구현 |

## 3. 시연 순서 (심사 대응용)

1. **통합일정** `/schedule` → '연쇄위험 판단 근거': 데모 일정 서천→보령 연결의 입력값·계산 과정·판단 근거 확인
2. 군산 CCTV 위치 재확인 카드 → '예상 종료' → 13:40, '현장 보고' → 미리보기(홍성: 위험 없음 → 위험 높음) → 저장
3. 같은 화면에서 홍성 연결의 '[연쇄위험 감지] 위험 높음 · 선행 현장 지연 · 예정값만으로는 보이지 않는 위험' 확인
4. '판단 이력' #1 '신규 위험' 확인 → 'JSON 내보내기'
5. 왼쪽 메뉴 '오늘의 업무' → '먼저 확인할 일'에서 '연쇄 지연 위험' 알림 확인
6. **기술검증 시뮬레이션** `/demo/verify` (실사 시연 화면 위쪽 '기술검증 시뮬레이션' 버튼) → 시나리오 B → D → E 순서로 확인, 연속 시험(정상→지연→조정) 실행 후 원상복구
7. 화면 아래 '기존 정적 충돌 검사와 비교' 표 확인
8. 오른쪽 위 메뉴 '데모 데이터 초기화'로 원래 데모 상태로 복구
