# 하나 AX 0.4.0 — UI/UX 전면 개편 기록

대상: `hana-project-ax@0.4.0` · 실증 화면(`/pilot/*`)과 브라우저 저장 실증판의 PC+Mobile 보기.

- 기능 · 엔진 · DB · 권한은 바꾸지 않았다. 화면 구성, 메뉴, 흐름, 입력 방식만 바꿨다.
- 참고한 방향은 두 가지다.
  - 여백이 넉넉한 미니멀 카드형 화면.
  - 선명한 주요 버튼 · 하단 탭 · 상태 칩.
- 특정 서비스의 화면 · 색 · 아이콘 · 문구는 가져오지 않았다. B2B 현장업무에 맞춰 새로 설계했다.
- 디자인 기준은 [`docs/DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md)에 있다.

> 이 문서의 화면 사진은 로컬 시험 DB의 **검증 시나리오(가상)** 자료로 찍었다.
> - 사람 · 현장 이름은 시험용이다.
> - 같은 컴퓨터의 브라우저 세션이며, 실제 휴대폰 시험이 아니다.
> - 현장 적용 실적은 여전히 **0건**이다.
> - 화면 개편에 따른 업무 효과(시간 단축 등)는 측정하지 않았으므로 쓰지 않는다.

## 1. 기존 화면에서 고친 점 (분석 결과)

| 구분 | 0.3.2의 문제 | 0.4.0에서 바꾼 것 |
|---|---|---|
| 현장 첫 화면 | 일정 카드에 버튼이 모두 같은 크기로 나열됨. '지금 무엇을 할지'가 따로 보이지 않음 | **지금 할 일** 카드에 현재 현장 · 상태 · 다음 행동 · 빠른 버튼(문제 보고 · 사진 첨부 · 안전점검)을 모음. **아래 고정 버튼**(작업 시작 / 작업 종료)과 **하단 탭 4개**를 둠 |
| 문제 보고 | 긴 한 화면 양식이었고, 사진이 올라가는 상태가 보이지 않음 | 전체 화면 **6단계 보고**: 유형 → 상태 → 지원 → 예상 종료 → 사진 → 보내기. 단계 진행 막대가 있고 보내기 버튼은 아래에 고정 |
| 사진 | 파일 고르기 칸 하나뿐 | **촬영 / 앨범** 버튼 · 미리보기 · 장별 상태(대기 · 올리는 중 · 완료 · 실패). 다시 누르면 **실패한 사진만 다시 올림** |
| 의견 보내기 | 일정 목록 아래에 늘 있음 | **내 기록** 탭으로 옮김 (지운 기능 없음) |
| 관리자 첫 화면 | 일정 표(일정판)라서 신규 보고 · 위험 · 안전점검을 한눈에 볼 수 없음 | **대시보드**를 새로 둠: 핵심 숫자 6개 · 우선 처리할 사건 · 연쇄 위험 현장 · 안전점검 · 최근 처리 결과 |
| 관리자 메뉴 | 위쪽 탭 6개가 모두 같은 비중 | **왼쪽 메뉴**: 주요 5개 + 더보기 2개. 모바일 폭에서는 위쪽 가로 메뉴. 날짜와 데이터 구분은 메뉴를 옮겨도 유지 |
| 사건 카드 | 한 줄에 정보가 몰려 읽기 어려움 | 상태 칩 → 현장 · 기사 → **다음 조치** → 우선 확인 이유 → 발견 · 보고 · 진행 · 요청 4칸 → 엔진 판단. 기록 근거는 '펼쳐보기'로 접음 |
| 사건 상세 | 인쇄용 증빙만 있음 | 화면 위쪽에 **사건 한눈에**를 둠: 문제 개요 → 현장 사진 → 관리자 조치 → 후속 현장 위험 · 조치 전후(**연쇄 영향 그림**). 아래 인쇄 증빙은 그대로 |
| 색 | 노란 띠 · 보라 점선 · 파랑이 섞여 뜻이 불분명 | 포인트 색은 인디고 하나. 상태 색은 뜻으로만 씀(위험 빨강 · 주의 주황 · 정상 초록). **시험 데이터는 회청색 점선**으로 통일 |

- 관리자: 더보기 · 펼쳐보기.
- 현장: 내 기록 탭.

## 3. 주요 흐름

### 3-1. 현장기사 — 첫 화면

1. 인사와 오늘 현장 수 · 날짜 넘기기 · 검증 시나리오 / 실제 업무 바꾸기 · 데이터 구분 띠.
2. **지금 할 일**(인디고 카드)
   - 작업 중인 현장, 없으면 아직 끝나지 않은 첫 현장을 보여 준다: 몇 번째 현장인지 · 예정 시각 · 바뀐 예상 종료 · 다음 행동 한 문장.
   - 빠른 버튼 3개는 그 현장 카드의 해당 기능을 바로 연다.
     - **문제 보고 · 지원 요청**
     - **사진 첨부**: 진행 중 사건이 있으면 그 사건에 사진을 추가하고, 없으면 문제 보고를 연다.
     - **안전점검**: 아직 안 한 첫 단계를 연다.
3. 오늘 요약: 현장 수 · 작업 종료 · 안전점검 n/전체 · 진행 중 요청.
4. **본사에서 온 소식**: 진행 중 사건의 마지막 본사 조치와 안전점검 보완 요청. 누르면 해당 현장 카드로 간다.
5. **방문 순서** 카드
   - 순서 번호 · 확인 → 시작 → 종료 진행 막대 · 기록된 단계(시각 정정 · 잘못 누름).
   - 큰 버튼: 업무 확인 / 작업 시작 / 예상 종료 보내기 / 작업 종료.
   - 사후 입력 · 안전점검 · 문제 보고.
6. **아래 고정**: 지금 현장의 작업 시작(또는 사진 · 작업 종료) 버튼 + 하단 탭 4개.
7. 결과 알림은 화면 아래에 뜬다: '○○ 작업 시작 기록됨 · 실제 시각 · 서버 기록 · 입력 방식'. 닫을 수 있고 12초 뒤 닫힌다.

전송 대기 · 기록 안 됨 알림, 휴대폰 보관 · 자동 재전송 · 중복 방지는 0.3과 같다. 대기열 처리 코드는 바꾸지 않았다.

### 3-2. 현장 문제 보고 (6단계)

`유형 → 상태(+ 발견 시각) → 필요한 지원 → 예상 종료 변경 → 사진 → 확인하고 보내기`

- 휴대폰에서는 전체 화면으로 열린다. 맨 위에 단계 진행 막대, 맨 아래에 **보고 보내기**가 고정된다.
- 첫 단계를 고르면 다음 단계로 자동으로 내려간다.
- 필수 항목, 발견 시각의 근거(현장 직원 진술 등), 보고 시각(버튼 누른 시각), 자료 구분(검증 시나리오 날짜), 원자료 이름 규칙은 0.3과 같다.
- 연결이 끊겨 실패해도 입력 내용은 그대로 남는다. '다시 보내기'를 누르면 같은 요청 번호로 한 번만 저장된다.

### 3-3. 사진 첨부

1. **촬영**(카메라) 또는 **앨범**(여러 장)으로 고른다.
2. 미리보기 바둑판이 나온다. 아직 올리지 않은 사진은 ✕로 뺄 수 있다.
3. 보내면 한 장씩 올린다.
   - 각 사진에 상태가 표시된다: **대기 → 올리는 중 → 완료 / 실패**.
   - 한 장이 실패해도 나머지는 계속 올린다.
4. 실패가 있으면 안내가 나온다. 다시 누르면 **실패한 사진만** 다시 올린다.

사진을 줄이고 촬영 정보를 지운 뒤 비공개 저장소에 올리는 과정은 0.3과 같다(`preparePhoto` · `uploadPhoto` 그대로). 보관 기한 · 서명 주소(10분)도 바꾸지 않았다. 사진 첨부는 다음 세 곳에서 같은 부품을 쓴다.
- 문제 보고
- 사건 사진 추가
- 안전점검 · 보완 사진

### 3-4. 관리자 — 대시보드

| 숫자 | 뜻 (어디서 세는지) |
|---|---|
| 운영 중인 현장 | 선택한 날짜 · 데이터 구분의 '예정' 일정 수 (작업 중 · 종료 수 함께) |
| 신규 문제 보고 | 처리 중 사건 중 '보고됨'(본사 접수 전) |
| 조치 대기 요청 | 처리가 끝나지 않은 사건 전체 (날짜와 관계없이 — '문제·지원'과 같은 기준) |
| 위험도 높은 현장 | 지금 시각 기준 기존 엔진 판단에서 '높음' 이상 연결의 후속 현장 수 (위험 연결 · 판단 보류 수 함께) |
| 안전점검 미완료 | 확인 대기 + 보완 중 + 오늘 시작 전 점검을 아직 안 보낸 현장 |
| 최근 처리 결과 | 선택한 날짜에 끝난 사건 (해결 · 그 밖) |

> 0.5.0에서 바뀐 점 (현장 책임자 통화 반영, [`docs/FOCUS_0.5.0.md`](FOCUS_0.5.0.md)):
> - **확인 필요 현장**을 추가했다.
> - '위험도 높은 현장'은 **후속 일정 영향**으로 이름을 바꾸고 맨 뒤로 옮겼다.
> - 안전점검 미완료는 3단계 **단계 누락** 기준으로 센다.
> - '최근 처리 결과'는 숫자 칸에서 빼고 오른쪽 목록 머리로 옮겼다.
> - 우선 처리 순서는 '본사 확인 전 · 지원 요청'이 후속 위험보다 앞이다.
>
> 0.6.0에서 다시 바뀐 점 (안전 1순위, [`docs/SAFETY_FIRST_0.6.0.md`](SAFETY_FIRST_0.6.0.md)):
> - 핵심 숫자 순서: 안전 확인 필요 · 연락 없이 늦어짐 · 신규 문제 보고 · 조치 대기 요청 · 다음 현장 지연 위험 · 운영 중인 현장.
> - 맨 앞에 '안전 확인 필요(1순위)'를 두고, 옆에 '연락 없이 늦어지는 현장(공동 1순위)'을 둔다.
> - 그 아래에 우선 처리할 사건, 그다음 '다음 현장 지연 위험(2순위)'을 둔다.

- **우선 처리할 사건**: 기존 우선 확인 순서(`rankCases`)의 앞 6건.
  - 카드마다 현장 · 기사 · 유형 · 발견 · 보고 시각 · 요청 지원 · 상태 · 후속 현장 위험(엔진 계산값) · **다음 조치**를 보여 준다.
  - 순서 계산은 '문제·지원' 화면과 같은 함수를 쓴다. 공용 함수 `loadRankedInbox`로 옮겼고 계산 방법은 그대로다.
- 개선율 · 절감 시간 같은 추정치는 보여 주지 않는다.

### 3-5. 관리자 — 사건 상세와 연쇄 영향 그림

- **사건 한눈에**(화면 전용)는 다음 순서로 보여 준다.
  1. 문제 개요(상태 · 자료 구분 · 발견 · 보고 · 요청 지원 · 다음 조치)
  2. 현장 사진
  3. 관리자 조치 타임라인
  4. **후속 현장 위험 · 조치 전후**
- 이 사건의 위험과 그날 전체의 위험은 나눠서 보여 준다.
  - 숫자 3개: 이 사건으로 새로 생긴 위험 · 조치로 풀린 위험 · 남은 위험.
  - 그날 전체 위험 연결 수는 '계산 근거 펼쳐보기' 안에 참고로 둔다.
- **연쇄 영향 그림**은 두 부분이다.
  - 사건 현장 → 1번째 후속 현장 → 2번째 … 사슬. 화살표 색은 지금 남은 위험이다.
  - 아래 연결마다 '보고 직후'와 '조치 후'의 등급 · 도착 여유/부족(계산값), 결과(해소 · 완화 · 남음 · 악화)를 나란히 둔다.
- 값은 인쇄 증빙과 같은 판단 기록(`result_before/after`)에서 읽는다. 다시 계산하지 않는다.
- 아래의 **인쇄용 사건 증빙**(1쪽 핵심 흐름 요약 + 상세 1~6)은 그대로 두었다. 새 패널은 인쇄에서 빠진다(`print:hidden`).

### 3-6. PC+Mobile 실증판

- PC 화면과 휴대폰 틀(390 / 430px)을 나란히 두는 구성은 그대로다.
- 위쪽에 **처리 흐름 띠**를 더했다: 현장 문제 발견 → 보고 → 위험 계산 → 관리자 지원 → 일정 조정 → 재판단.
  - 지금 세트의 마지막 현장 문제가 어디까지 왔는지 보여 준다.
  - 위험 계산 · 재판단 칸에는 기록된 판단의 위험 연결 수(전 → 후)를 쓴다.
  - 새로 끝난 단계는 잠깐 강조된다.
- 띠에 '같은 브라우저 안의 PC 화면과 휴대폰 크기 화면입니다 — **실제 다른 기기 사이 시험이 아닙니다**'를 늘 표시한다.

## 4. 보존 확인

## 9. 0.4.1 보완 (2026-11-16) — 화면이 어디 있는지 · 기존 기능도 Mobile · PC+Mobile로

사용자 확인 영상에서 두 가지가 드러났다.
1. 배포 화면에서 '바뀐 게 없다'고 보였다. 0.4.0 개편의 대부분은 **실증 시스템(`/pilot`, 로그인 · 중앙 DB)** 화면인데, 앱 안 어디에도 그 화면으로 가는 링크가 없었다. 영상에서 본 화면은 **브라우저 저장 실증판(`/`)**이고, 이 화면에는 처리 흐름 띠만 더해졌다.
2. Mobile · PC+Mobile 보기에서는 실증판 4개 화면만 보였다. 기존 기능(오늘의 업무 · 통합일정 · 프로젝트 등)으로 갈 메뉴가 없었다.

고친 것:

| 항목 | 내용 |
|---|---|
| 실증 시스템 바로가기 | 왼쪽 메뉴의 실증 메뉴 아래에 **실증 시스템 (로그인) — 현장기사 · 관리자 · 중앙 DB**를 두었다. 실증 홈에도 같은 카드를 두었다. 누르면 `/pilot`(로그인)으로 간다 |
| 전체 메뉴 | Mobile · PC+Mobile 보기 머리글에 **전체 메뉴** 버튼을 두었다. 휴대폰 틀 하단 메뉴에는 **전체** 버튼을 두었다. 둘 다 왼쪽 메뉴 전체(실증 메뉴 · 실증 시스템 · 기타 · 기존 기능)를 연다 |
| 기존 기능도 PC / Mobile / PC+Mobile | 기존 기능 화면 머리글에도 보기 전환을 두었다. Mobile · PC+Mobile을 고르면 실증판과 같은 틀로 보여 준다: 왼쪽 PC 화면 + 오른쪽 휴대폰 틀. 둘 다 같은 화면이고 경로를 옮기면 함께 따라간다. PC 보기의 기존 화면은 원래 틀 그대로다 |
| 휴대폰 틀 높이 | 머리글이 두 줄이 돼도 휴대폰 틀 아래가 잘리지 않게, 남은 높이를 채우도록 바꿨다 |

- 실증 시스템(`/pilot`)과 서비스 안내(`/store`)는 자체 화면 틀을 쓰므로 이 보기 전환에 넣지 않았다. 실증 시스템 휴대폰 화면은 휴대폰에서 직접 연다.
- 배포 환경에서 `/pilot`을 쓰려면 Supabase 연결 설정(공개 주소 · 공개 키)이 Vercel에 들어가 있어야 한다. 없으면 '실증 DB가 아직 설정되지 않았습니다'가 나온다 (`docs/FIELD_SYSTEM_SETUP_GUIDE.md`).
- 시험: `lab.mjs` 12번에 4개 검사를 더했다.
  - 메뉴의 실증 시스템 바로가기.
  - 기존 통합일정의 PC+Mobile 동시보기.
  - 전체 메뉴로 기존 기능 이동 시 휴대폰 틀이 따라감.
  - PC 보기로 돌리면 원래 틀.
- 전체 회귀 (2026-11-16 11:42~11:49 KST): **629 / 629 통과**

## 11. 0.4.3 (2026-11-16) — 실증 홈 '예시 기록 2건'

사용자 확인: 둘러보기를 봤는데 실증 홈에 아무 기록도 보이지 않았다. 원인은 두 가지였다.
1. **실증 홈(`/`)은 브라우저 저장 실증판이다.** 기록은 그 기록을 입력한 브라우저에만 남는다. 둘러보기는 개발 환경의 로컬 시험 DB와 자동 브라우저에서 돌렸으므로 사용자 브라우저에는 남지 않는다.
2. **배포 화면의 실증 시스템(`/pilot`)은 아직 중앙 DB에 연결되지 않았다.** 2026-11-16 확인 결과, 배포 주소의 `/pilot`이 '실증 DB가 아직 설정되지 않았습니다'를 보여 준다. Vercel에 Supabase 공개 주소와 공개 키가 들어가야 한다 (`docs/FIELD_SYSTEM_SETUP_GUIDE.md`).

고친 것:
- 실증 홈에 **예시 기록 2건 만들기** 버튼을 두었다.
  - 누르면 **그 브라우저에** 가상 시나리오 세트 2개가 만들어진다(둘러보기 사례와 같은 이야기).
  - 화면 버튼과 같은 입력 함수로 넣고, 위험 판단도 같은 엔진이 계산한다.
    - 예시 1: 보고 직후 위험 2건 → 일정 조정 뒤 1건 남음 → 해결.
    - 예시 2: 보고 직후 위험 1건 → 예상 종료 다시 입력으로 해소 → 임시 조치.
  - 만든 뒤 현장 실증 화면으로 넘어간다.
- **예시 기록 지우기**: 예시 세트와 그 입력 · 판단 · 현장 문제, 예시 기사만 뺀다. 다른 기록은 그대로다.
- 최근 입력기록에서 가상 시나리오 기록의 시각을 '실제'가 아니라 '가상 시각'으로 표시한다.
- 시험:
  - `tests-pilot/examples.test.ts` 5개: 엔진 결과 · 중복 방지 · 지우기 범위.
  - `lab.mjs` 3개: 버튼 → 기록 표시 → 지우기.
- 일정판 간헐 실패의 원인을 확인했다 (0.3.1부터 '원인 미확정'으로 남아 있던 항목, 실기기 시험 A17).
  - 일정을 취소하면 '취소했습니다' 안내가 먼저 뜨고, 일정판의 '이동 기준 재확인 필요' 요약은 **최대 약 0.2초 뒤에** 다시 그려진다.
