# 0.6.0 안전 1순위 — 우선순위 재조정 · 점검 · 고도화 (2026-11-16)

> **우선순위** (2026-11-16 사용자 지시)
> 1. **안전**: 1순위.
> 2. **막힘 조기 보고와 본사 지원**: 공동 1순위. 안전 바로 다음에 둔다.
> 3. **다음 현장 지연**: 2순위. 0.5.0의 '보조'에서 올렸다.
>
> 엔진(연쇄위험 판단엔진)과 DB 스키마 · RLS · 인증 · 기록은 바꾸지 않았다. 새 마이그레이션이 없다.
> 관련 법령 정리: [`docs/SAFETY_LAW_NOTES.md`](SAFETY_LAW_NOTES.md) (법률 자문 아님).

## 1. 근거

- **사용자 지시 (2026-11-16)**
  - 안전 수칙이 안 지켜지면 생명이 위험할 수 있다.
  - 위반하면 거래가 끊기거나, 심하면 면허가 정지될 수 있다.
  - 그래서 안전을 1순위로 둔다. 다음 현장 지연은 2순위다.
- **통화 (2026-11-13, 구본석 이사)**
  - 다치면 산재다.
  - 안전기준이 강화돼 계약 취소 · 퇴출까지 갈 수 있다.
  - "하나도 빠지면 문제".
- **법령 정리** ([`SAFETY_LAW_NOTES.md`](SAFETY_LAW_NOTES.md))
  - 영업정지 요청과 공공 입찰 제한은 대부분 사망 사고가 기준이다.
  - 미착용 자체도 처벌 대상이 될 수 있다. 사업주는 벌칙, 근로자는 과태료다.
  - 그래서 사고 전 단계의 확인 기록이 중요하다.

## 2. 0.5.0을 안전 1순위 관점에서 점검한 결과

### 이미 잘 돼 있던 것 (그대로 유지)

- 안전점검 3단계(시작 전 · 진행 중 · 마친 뒤)마다 착용 사진이 필수다. 사진이 없으면 제출할 수 없다.
- 사진만으로 적합 처리하지 않는다. 관리자 육안 확인 기록으로만 적합이 된다.
- 미흡 항목을 고르면 "작업을 멈추고 직접 연락" 안내가 바로 나온다.
- 보완 요청 → 보완 사진 → 조치 완료 확인까지 기록이 남는다.
- 문제 보고 가운데 '안전 위험'은 우선 처리 순서 맨 앞이다.

## 3. 0.6.0에서 바뀐 것

### 현장 직원 휴대폰

- **작업 시작 · 종료 전 안전점검 확인 창**
  - 시작 전 점검 없이 '작업 시작'을 누르면 "시작 전 안전점검을 먼저 보내 주세요"가 뜬다.
    - [시작 전 점검 하기]: 그 현장의 시작 전 점검을 바로 연다.
    - [점검 없이 시작]: 기록은 되지만 본사에 '점검 전 작업 시작'으로 표시된다.
  - 마무리 점검 없이 '작업 종료'를 누를 때도 같다. 진행 중 점검이 없으면 그것도 함께 알린다.
  - 늘 "위험한 상황이면 작업을 멈추고 바로 전화" 안내를 함께 보여 준다.
  - 사후 입력(시각을 놓친 경우)과 정정에는 이 창이 뜨지 않는다.
- **지금 할 일 카드**: 시작 전이고 점검이 없으면 "① 시작 전 안전점검 → ② 작업 시작"과 [시작 전 안전점검 하기]를 먼저 보여 준다.
- **빠른 버튼 · 아래 메뉴 순서**: 안전점검이 맨 앞이다 (오늘 일정 · 안전점검 · 문제 보고 · 내 기록).

### 관리자 대시보드 (위에서 아래 순서)

1. **핵심 숫자**: 안전 확인 필요 · 연락 없이 늦어짐 · 신규 문제 보고 · 조치 대기 요청 · 다음 현장 지연 위험 · 운영 중인 현장.
2. **안전 확인 필요 (1순위)**와 **연락 없이 늦어지는 현장 (공동 1순위)**: 넓은 화면에서는 나란히 놓는다.
   - 안전 쪽의 '즉시 확인'(빨강): 미흡 · 안전 위험 보고 · 보완 중 · 점검 없이 시작 · 마무리 점검 없이 종료.
   - 안전 쪽의 '그 밖'(주황): 진행 중 점검 누락 · 시작 뒤 · 종료 뒤 제출 · 사진 확인 대기.
   - 목록 순서: 미흡 · 안전 위험 · 보완 중 → 점검 없이 시작·종료 → 그 밖. 같은 묶음 안에서는 최근 것부터 보여 준다.
     - 이 순서를 정한 이유: 시험 기록이 많을 때, 방금 생긴 '마무리 점검 없이 종료'가 오래된 항목에 밀려 목록에서 빠지는 문제가 회귀 시험에서 드러났다.
   - 연락 없이 늦어지는 쪽: 예정을 넘긴 현장마다 **"지금 끝나도 다음 현장 ○○ 도착 N분 부족 (계산값) · 고객 연락 검토"** 또는 "다음 현장 영향 없음"을 보여 준다.
     - 기존 엔진에 '지금 예상 종료 보고' 가정 기록 하나를 더해 계산한다. DB에는 저장하지 않는다.
3. **우선 처리할 사건**: 순서 규칙은 0.5.0과 같다. 안전 위험 · 긴급 → 본사 확인 전 → 지원 요청 → 후속 영향.
4. **다음 현장 지연 위험 (2순위)**: 연쇄위험 판단엔진 계산값. 그다음에 최근 처리 결과를 둔다.

### 안전관리 화면

- 현장별 3단계 현황 표에 시점을 함께 보여 준다: '누락 · 없이 시작', '누락 · 없이 종료', '시작 뒤 제출', '종료 뒤 제출'.

### 성과 측정

- **핵심 지표 순서**
  1. 안전점검 3단계 (측정 10, 1순위)
  2. 발견 → 보고 → 확인 → 지원 결정 (측정 1~3, 공동 1순위)
  3. 다음 현장 지연 (측정 5·6, 2순위)
- **측정 10에 추가한 것**
  - 작업을 시작한 현장 가운데 시작 전 점검을 **작업 시작 전에** 낸 현장 수.
  - 마무리 점검을 종료 전에 낸 현장 수.
  - 제출 → 관리자 첫 확인(적합 확인 또는 보완 요청) 시간. 중앙값 · 범위 · n으로 보여 준다.
  - 아직 확인 안 된 점검 수.

## 4. 바뀌지 않은 것

- 엔진 계산 · 규칙 버전, DB 스키마 · RLS · 인증 · 기록. 새 마이그레이션은 없다.
- 운영 SQL 묶음은 버전 글자만 0.6.0으로 바뀐다. 0.3.2 이후 묶음을 이미 적용했다면 다시 적용할 필요가 없다.
- 점검 항목(초안)과 필수 항목. 회사 기준으로 확정할 일이다 ([법령 정리 4장](SAFETY_LAW_NOTES.md)).
- '점검 없이 시작'의 사유를 따로 받지 않는다. 받으려면 DB 변경이 필요해 승인을 받아야 한다. 지금은 시각 비교로만 표시한다.

## 5. 다음 단계 후보 (승인 · 확인 필요)

1. **점검 항목 확정**: 법령 조항과 발주처 기준에 맞춘다. 예: 정전작업의 잠금·꼬리표·검전, 사다리 3.5m 이하. 구본석 이사 확인이 필요하다.
2. **'점검 없이 시작' 사유 입력**: 예를 들어 "고객 요청으로 바로 착수". DB 변경이 필요하다.
3. **관리자 확인 목표 시간 설정과 넘김 알림**: 회사가 목표 시간을 정해야 한다.
4. **신규 직원 표시**: 막힘 조기 확인을 더 일찍 묻는 데 쓴다. DB 변경이 필요하다.
5. **반기 안전 점검 보고서 내보내기**: 중대재해처벌법 시행령의 반기 점검 · 5년 보관에 쓸 수 있는 형태다. 기존 기록만으로 만들 수 있다.
